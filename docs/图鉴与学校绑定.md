# 图鉴收集与学校绑定

> 2026-10-24 改版。解决两件事：**图鉴按学校统计**（新用户没绑学校时不该有进度），
> 以及**用户可以自己选校 / 申请新建学校**（以前只有超管能建校，普通用户只能看着「未绑定学校」）。

## 一、图鉴口径：一切以「本校」为准

| 项 | 规则 |
|---|---|
| 总数 `total` | 用户**当前绑定学校**的在册猫数（`cats.schoolId === user.schoolId`）|
| 已收集 `seen` | 本校猫 id ∩ `users.catSeen`，只算交集 |
| 未绑定学校 | `needSchool: true`，`total/seen/percent` 全为 0，**不返回任何猫** |

两条都是踩过的坑：

1. **未绑定时不能复用 `listCats`**：它的 `where` 在没有 `schoolId` 时是空的，会返回**全环境**的猫。
   新用户一进来就显示「0 / 4」，那 4 只是别校的猫 —— 凭空给了一个进度条。
2. **已收集不能直接取 `user.catSeen.length`**：`catSeen` 是跨校累计的。
   用户换过学校后，旧学校拍到的猫仍在这个数组里，会出现「已收集 7 / 总数 4」。

换校后再次进入，图鉴自动切到新学校；旧学校的收集记录不丢（仍在 `catSeen` 里），
只是不计入新学校的进度 —— 重新绑回旧学校就恢复。

## 二、页面分工

| 位置 | 内容 |
|---|---|
| 我的 → 三格统计 | 猫粮值 / 打卡次数 / **图鉴数**（本校已收集，与入口数字一致） |
| 我的 → 菜单「图鉴收集」 | 右侧显示 `已收集 / 本校总数`（未绑学校时显示「未绑定学校」），点击进图鉴页 |
| `pages/dex/dex`（图鉴收集） | 进度头（学校 + 已收集/总数 + 进度条）+ 3 列解锁墙 |
| `pages/mine`（学校卡片） | 下拉选校 / 申请新建 / 审核状态 |

**为什么进度墙要独立成页**：原来「我的」页塞了 8 格图鉴墙，把打卡记录与菜单挤到很下面；
而图鉴本身是一屏要滑的内容，放个人主页上既不合定位也看不全。

图鉴格子的表现：

- 已解锁：头像 + 猫名 + 花色标签，点击进猫档案；
- 未解锁：`?` + 「未解锁」+ 花色线索（如「狸花」），**不请求头像**（省流量），点击只提示「还没遇到过这只猫」。

## 三、学校绑定流程

```
我的 → 学校 → 「选择学校」下拉
   ├─ 选已有学校  → 立即绑定（学校已由超管建过/审核过，不需要再审）
   └─ 下拉里没有  → 「没有我的学校？申请新建」
                      ├─ 普通用户 → 落 school_applies（status=pending）→ 超管审核
                      └─ 超管     → 直接建校并绑定
```

关键决定：

1. **选已有学校不审核**。学校文档本身是超管建过（或审核通过的申请建的），再让用户等一次没有意义。
2. **新建学校先审后建**。申请阶段**不预建** `schools` 文档 —— 预建的话它会立刻出现在
   `listSchools` 里，别的用户能选到一所「还没人审过」的学校，审核就形同虚设。
   审核通过时才 `schools.add()` + 绑定申请人。
3. **同一用户只保留一条待审**：连点/反复提交会把审核列表刷满，管理员处理一条又冒三条。
4. **审核并发安全**：`handleSchoolApply` 用条件更新抢占（`status='pending'` 才写 `approving`），
   两个管理员同时点「通过」只有一份成功，另一份收 409。否则会给同一申请建出两所学校。
   建校失败会把状态**退回 pending**，卡在 `approving` 的申请既不在待审列表、也不能再通过，等于永久丢失。
5. **审核时再跑一次文本安全检测**：管理员可能直接点通过没细看，而学校名会展示给全校。

## 三·四、测试校园 / 未开放校区：只对超管可见（2026-10-25）

需求：像「东南大学-测试」这种校园**不进普通用户的选校下拉**，但超管要能看见、能改。

判定（`cloudfunctions/catcampus/index.js` 的 `isSchoolHidden`），**显式字段优先**：

| 学校文档 | 结果 | 说明 |
|---|---|---|
| `hidden: true` | 隐藏 | 超管在后台「对普通用户」开关里设置，精确控制 |
| `hidden: false` | **可见**（即使名字带「测试」） | 兜底是启发式，必须给超管翻案权 |
| 未设 `hidden` + 校名含「测试」/`test` | 隐藏 | 兜底：部署即生效，不需要任何数据迁移 |

为什么要有名字兜底：测试校园是超管自己建的，建的时候不会记得先勾「隐藏」，
等它出现在全校学生的下拉里才发现 —— 那时已经有人绑上去了。名字兜底让「叫测试的校园」
从建好那一刻起就不进用户视野。

挡在哪些地方（**只挡 UI 是不够的**）：

- `listSchools`（用户选校下拉的唯一数据源）：非超管过滤掉隐藏校园，**超管看全量**
  —— 否则一所隐藏学校就成了改不动的僵尸数据。
- `applySchool` / `bindSchool`：这两个是**按 id 直接绑**，知道 id 就能绕过下拉，
  所以统一走 `assertSchoolBindable()`，非超管绑隐藏校园 → 403「该校园未开放」。
- `listSchoolsAdmin`：后台**不过滤**，并回一个算好的 `hidden` 供 UI 打标
  （列表行显示「仅超管可见」红色标记 + 编辑面板里可切换）。

`getSchool` 刻意不改：已绑定隐藏校园的用户仍要拿到地理信息，
否则他的首页/地图会直接崩 —— 隐藏的是「可选列表」，不是「已绑定关系」。

回归：`scripts/test_school_hidden.js`（27 项）。

## 三·五、首页顶部学校名

校名严格跟随**已绑定学校**，未绑定时整块不渲染（不再用「喵园」占位 ——
占位名会让人误以为自己已经选好学校）。模板里由 `wx:if="{{school}}"` 控制，
未绑定时 `.hero` 加 `no-school` 保持右上角徽章靠右，不至于甩到最左边。

联动靠三层，缺一层就会出现「校名换了、数字还是上一所的」：

| 层 | 做什么 |
|---|---|
| `app.setSchool(school)` | 唯一写全局学校的入口；**跨校时作废 `homeOverview`**（统计按校隔离），同校只更新字段 |
| `app.refreshUser()` | 发现 `user.schoolId` 与本地 school 不一致（换校/解绑）→ 清空 school 与概览缓存 |
| `index.onShow()` | `syncIdentity()` 比对当前渲染的 school id：变了就清 overview 重拉，没变才走后台刷新 |

另有两条兜底：

- `index.load()` 发现 `user.schoolId` 有值但 `globalData.school` 为空 → 补拉一次 `getSchool`（自愈，避免一直显示「未绑定」）。
- 下拉刷新带 `force` 参数绕过 `homeOverview` 缓存 —— 原实现只清 `data.overview`，
  `load()` 仍读全局缓存，等于**下拉没刷**。

## 四、接口

| action | 权限 | 说明 |
|---|---|---|
| `listDex` | user | `{brief:true}` 只回计数（「我的」页用）；否则回清单（最多 200 只，`truncated` 标记超限） |
| `applySchool` | user | 传 `schoolId` → 直接绑定；传 `name` 等 → 落待审申请 |
| `mySchoolApply` | user | 我最近一条 pending / rejected 申请 |
| `listSchoolApplies` | admin（内部 `requireSuper`） | 待审列表 |
| `handleSchoolApply` | admin（内部 `requireSuper`） | `{id, approve}`；通过 = 建校 + 绑定申请人 |

`bindSchool` 保留（老版本前端在用），但补了存在性校验：绑一个不存在/已删除的 `schoolId`
之后，用户所有列表都会 `where({schoolId})` 查空，界面表现为「学校有了、数据全空」，比直接报错难查得多。

## 五、数据

新增集合 **`school_applies`**（`lib/core.js` 的 `COL.schoolApply`）：

```js
{ _id, openid, _openid, nickName, name, campus, city, intro, status, handler, handledAt, schoolId, createdAt }
// status: pending | approving（审核中，内部态）| approved | rejected
```

集合总数从 14 变 15 —— 部署后调一次 `initCollections`（幂等），或在控制台手工建。
写操作前有惰性建表兜底，但**首次部署别赌**。
