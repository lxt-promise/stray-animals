# 喵园 CatCampus 技术难点落地说明

本文记录六个技术难点在代码中的**实际落地方式**、需要你在云开发控制台做的配置，以及后续升级路径。
代码位置均相对 `E:\Agent\project\stray-animals`。

---

## 0. 架构调整（本次重构）

原来的单文件云函数已分层，`index.js` 只保留 action 注册表与业务编排：

```
cloudfunctions/catcampus/
├── index.js            # ACTIONS 表驱动路由（32 个 action）
└── lib/
    ├── core.js         # DB 句柄 / 集合常量 / 角色鉴权 / 多校隔离 / 坐标脱敏 / 工具
    ├── security.js     # 内容安全（文本 · 图片 · 异步媒体）
    ├── points.js       # 猫粮值原子发放（事务 + 日上限）
    ├── tnr.js          # TNR 状态机
    ├── vision.js       # AI 识别（特征 → 检索 → Top-N → 异步任务 → 人工确认）
    └── map.js          # 地图点位网格聚合
```

**表驱动路由**：新增接口只改 `ACTIONS` 一张表，声明 `handler` 与所需角色，鉴权由统一入口完成：

```js
'listCats': { role: 'public', handler: listCats },   // public | user | member | admin
```

统一签名 `handler(me, event, ctx)`，`ctx.openid` 为当前用户。另有超时保护
（`ACTION_TIMEOUT_MS`，默认 15s）与 `AppError` 语义码（401/403/404/409/500）。

**单函数体积治理**：公共机制全部抽到 `lib/`，本文件无第三方依赖，`node_modules` 只有 `wx-server-sdk`。
将来真遇到 50MB 上限，按域拆函数时 `lib/` 可直接复用，业务编排无需重写。

## 1. AI 猫脸识别（⭐⭐⭐⭐⭐）

### 落地的 pipeline

```
上传 fileId → 内容安全 → 特征提取 → 档案库检索 → Top-N 候选 → 人工确认 → 回写特征库
```

| 环节 | 实现位置 | 说明 |
|------|---------|------|
| 上传 | `pages/recognize/recognize.js` | `wx.chooseMedia` → `wx.cloud.uploadFile` |
| 内容安全 | `lib/security.js` | 图片 `imgSecCheck`；视频走 `mediaCheckAsync` + 封面帧同步检测 |
| 特征提取 | `lib/vision.js` | 配了 `AI_ENDPOINT` 走第三方；否则内置占位引擎（同图结果稳定） |
| 检索 | `lib/vision.js` `scoreCat()` | 属性匹配 + **位置先验**融合；有 embedding 时升级为余弦相似度 |
| 候选 | 同上 | Top-5，带分数与理由；低于阈值 55 标记 `lowConfidence` 提示人工确认 |
| 确认回写 | `confirmRecognize` | 写 `ai_samples` 样本；有 embedding 时写入猫档案 `embedding` 字段 |

### 关于「要不要自己训练模型」

**不需要。** 训练是改模型权重，建特征库只是把照片转成向量存起来，后者用的是别人训好的模型。
本项目的特征库是**增量自增长**的：每次用户点「就是它」，就把这次的 embedding 写进该猫档案，
同时落一条 `ai_samples` 标注样本。等哪天想微调，训练集已经攒好了。

需要自训练的信号（三者同时满足再说）：每只猫 ≥20 张不同角度照片、猫总数 >100、同花色频繁认错。

### 短视频识别

- 云函数 Node 环境**没有 ffmpeg**，真抽帧需上云托管容器或 Python 云函数；
- 当前用 `wx.chooseMedia` 返回的 `thumbTempFilePath`（封面帧）作为代表帧，零额外成本；
- `frames` 字段表示「计划抽帧数」，留给将来的容器化服务。

### 异步化（避免云函数超时）

视频走 `recognizeStart` → `recognizePoll`：

1. 建任务记录（status `pending`）立即返回 `taskId`；
2. 前端每 1.2s 轮询一次，最多 20 次；
3. 轮询时用「租约抢占」保证只有一个请求真正计算：把 `pending` 改成 `running` 并写 `leaseUntil`，
   抢到的才执行，其余直接返回「处理中」。租约 30s 过期后可被接管，避免执行者被中断导致任务卡死。
4. 重复轮询幂等，不会重复调第三方接口烧钱。

图片走 `recognize`（同步），一次请求拿结果。

### 接入第三方模型

在云函数配环境变量即可，前端零改动：

| 变量 | 说明 |
|------|------|
| `AI_ENDPOINT` | 视觉服务地址，POST JSON |
| `AI_TOKEN` | Bearer 令牌（可选） |
| `AI_TIMEOUT_MS` | 超时，默认 8000 |

请求体：`{ url, fileId, type, frames, schoolId, cats: [{id,name,pattern,color,photos}] }`
期望返回：`{ features: { tags:[{k,v}], pattern, color, embedding? }, candidates?: [{catId, score, reason}] }`

> 若只返回 `features` 不返回 `candidates`，服务端会用本地检索逻辑补候选，因此第三方只需做特征提取。

## 2. 数据隔离与安全架构（⭐⭐⭐⭐）

- **三级权限**：`lib/core.js` 的 `requireRole(user, minRole)`，等级表 `{ visitor:0, member:1, admin:2 }`，
  在 `ACTIONS` 表声明后由统一入口校验，不再散落在各 handler。
- **多校隔离**：`resolveSchoolId()` 解析、`assertSchool()` 校验归属，防止传参越权访问别的学校数据；
  所有列表查询强制带 `schoolId` 过滤。
- **位置模糊化**：`blurLocation(loc, radiusM)` 约 ±120m 偏移，偏移由坐标本身取种子 ——
  同一坐标结果稳定（可缓存）但无法反推真实位置。对幼猫、病猫、`spotPrivate` 点位生效，
  在**服务端**返回前统一处理，客户端拿不到就是拿不到。
- **字段脱敏**：`sanitizeCat()` / `sanitizeSighting()` 对非成员剔除 `internalNote`、`medicalNote`、`contact`。

数据库集合权限请设为「仅管理端可读写」，客户端一律走云函数。

## 3. 单函数 action 分发的工程问题（⭐⭐⭐⭐）

- 表驱动见上文第 0 节；
- 超时：`ACTION_TIMEOUT_MS`（默认 15s）；AI 类云函数可在控制台单独放宽到 60s；
- 体积：无第三方依赖，`lib/` 可直接被拆分后的多个云函数复用；
- 静态校验：`scripts/check.js` 会校验 action 注册表、lib 依赖存在性，
  **以及前端 `callApi('xxx')` 调用的 action 是否都已注册**（防止前后端对不上）。

## 4. 积分与游戏化的并发问题（⭐⭐⭐⭐）

`lib/points.js`：日上限不再靠「先查打卡次数再算」（典型 read-modify-write 竞态），
改为在用户档案维护 `pointsDay` / `pointsToday` 两个字段，
放进 `db.runTransaction` 里「读用户 → 算额度 → 原子自增」。

- 日上限 **60**，单次：打卡 +10 / 新猫 +30 / 首次遇见 +20 / TNR +50 / 人工确认 +5；
- TNR 不受日上限约束（重投入行为不该被打卡额度挤掉）；
- 事务不可用时降级为 `_.inc` 原子自增（增量本身原子，仅日上限在极端并发下可能略超）。

`scripts/_cf_test.cjs` 里有 8 次并发打卡用例，断言总额不超过 60。

## 5. TNR 状态机与联动（⭐⭐⭐）

`lib/tnr.js` 用白名单表定义流转（取值与 `utils/const.js` 的 `TNR_STATUS` 一致）：

```
待抓捕 → 诱捕中 → 已捕获 → 手术中/住院 → 已放归 → 转领养（终态）
   ↓         ↓         ↓
失败/逃脱 → 待抓捕（可重新安排）
```

- 非法流转直接拒绝，错误信息会列出「允许变更为：…」，终态提示「（终态，不可变更）」；
- 阶段日期自动回填（抓捕日 / 手术日 / 放归日），不覆盖人工填写；
- **联动一致性**：TNR 记录与猫档案在同一个事务里写，绝育完成同步
  `sterilized='yes'`、`earMark`、`status='campus'`，诱捕中标记 `tnrInProgress=true`；
- 前端 `tnr-edit` 调 `getTnrFlow` 拿白名单，选择器里只出现合法后继状态。

## 6. 校园猫地图（⭐⭐⭐）

`lib/map.js` + `listMapPoints`：

- **网格聚合**：网格边长随 zoom 变化（`0.01 / 2^(zoom-12)` 度），同格多只猫合并成 cluster，
  前端渲染成数字气泡，点击自动放大一级展开为单点。自己实现，无需 mapbox。
- **两级可见**：非成员拿不到 `spotPrivate` 点位，其余按幼猫/病猫规则模糊化；
  返回体带 `scope: 'public' | 'member'` 便于前端区分。
- 前端 `pages/map/map.js` 优先用聚合接口，失败自动降级为 `listCats` 直读，页面不会白屏。

## 需要你在云开发控制台做的配置

### 新建集合

> **一键做法**：部署云函数后，在小程序开发者工具 Console 执行
> ```js
> getApp().callApi('initCollections', {}).then(console.log)
> ```
> 会自动建齐全部 14 个集合并返回清单，幂等可重复调用。推荐用这个，别手工一个个建（容易漏）。

如果手工建，除 `docs/部署指南.md` 列出的 8 个基础集合外，还需补这些：

| 集合 | 用途 | 漏建时的表现 |
|------|------|------|
| `points` | 猫粮流水（记录表，与 users 分离） | 「猫粮明细」空白 |
| `ai_tasks` | AI 识别异步任务（含租约、结果、确认状态） | 首次识别报 `-502005` |
| `ai_samples` | 用户确认的识别样本（人机协同闭环，为将来训练攒数据） | 首次确认报 `-502005` |
| `vpay_orders` / `vpay_notifies` / `vpay_deliveries` | 虚拟支付订单 / 推送事件 / 发货意图 | 支付相关接口报错 |

权限同样设为「仅管理端可读写」。

> 代码里已加**集合自愈**：写操作前会先 `ensureCollection(name)`，漏建时尝试自动补建。
> 但依赖云函数账号是否有建表权限，控制台手工建仍然是最可靠的方式。

### 新增字段（存量集合无需迁移，缺失时代码有兜底）

- `users`：`pointsDay`（字符串）、`pointsToday`（数字）—— 日上限计数；
- `cats`：`embedding`（数组）、`embeddingFrom`、`tnrInProgress` —— 特征库与诱捕标记。

### 环境变量（可选）

`AI_ENDPOINT`、`AI_TOKEN`、`AI_TIMEOUT_MS`、`ACTION_TIMEOUT_MS`、
`SEC_OFF=1`（本地调试关闭内容安全检测，**生产环境不要开**）。

## 后续升级路径

1. **接真模型**：配 `AI_ENDPOINT` 指向自建服务（推荐 Qwen3-VL-Flash 级别，约 0.01 元/张），
   返回 embedding 后检索自动升级为向量余弦，属性匹配作为兜底；
2. **真抽帧**：短视频量起来后，上云托管容器装 ffmpeg，每 2 秒抽一帧，多帧投票合并结果；
3. **向量库**：猫超过 500 只再考虑 Cloud VectorDB / pgvector，当前内存 O(n) 完全够用；
4. **拆云函数**：真遇到体积或超时瓶颈时，按 `公共 / 社团 / AI / 管理` 拆 4 个，`lib/` 直接复用。
