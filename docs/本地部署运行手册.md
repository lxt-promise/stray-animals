# 自建识别服务 · 本地部署运行手册

> 配套文件：`server/`（服务端代码）、`docs/自建识别服务方案.md`（整体技术选型论证）
> 本文聚焦三件事：**它怎么工作的**、**本机环境缺什么**、**一步步怎么跑起来**。

---

## 一、这份服务在整个系统里的位置

喵园的识别能力横跨三端，搞清楚边界很重要：

| 端 | 职责 | 能不能做到的事 |
|---|---|---|
| **微信小程序** | 拍摄/选素材、上传云存储、展示候选结果 | ❌ 跑不了模型（几十 MB 权重塞不进小程序包，且性能不够） |
| **微信云函数 `catcampus`** | 鉴权、内容安全、编排、编排融合打分 | ❌ 没有 ffmpeg、不能长时间运行（上限 60s）、Python 环境不可用 |
| **自建识别服务**（本目录） | 跑模型、抽视频帧、维护特征库 | ✅ 任意装系统包、可选 GPU、无时长限制 |

一句话：**这个服务只负责"看图说话"，业务判断和权限仍然在云函数里**。云函数把图片的可下载链接 POST 过来，服务端返回标准化的候选列表，格式与 `cloudfunctions/catcampus/lib/vision.js` 的契约严格一致，所以**前端一行代码都不用改**。

## 二、实现原理

### 2.1 最容易搞混的一件事：这里没有任何"训练"

很多同学以为"做猫脸识别 = 训练模型"。其实这是两件事：

- **训练模型**：修改网络权重，需要每只猫几十张标注照 + 上百只猫 + GPU 跑几天。
- **建特征库**：拿别人已经训练好的模型，把每张照片转成一个数字向量存起来。

本项目里什么都训，只做建库。原因是：像 DINOv2 这类**自监督预训练骨干**，已经在海量图像上学会了"把图片压缩成有区分度的向量"这个通用能力——它知道两张图是不是同一个东西，尽管它从没见过你校园里的猫。

> 类比：你不需要为了"认出同班同学"而重新发育一遍视觉系统， retina 和 visual cortex 早已准备好，你要做的只是**记住他们的脸**。

### 2.2 单张图片的完整流水线

```
图片 URL
  │
  ├─① 下载并转 RGB            media.fetch_image()
  │
  ├─② 猫体检测（可选）        YOLOv8n ONNX，COCO 里 cat 的类别号 = 15
  │     取出面积最大的框，把背景裁掉
  │     └─ 为什么要这步？见下方「背景陷阱」
  │
  ├─③ 预处理                  letterbox 补灰边保持长宽比
  │     缩放到 224×224（DINOv2 官方分辨率）
  │     ImageNet mean/std 归一化 → [1,3,224,224] 张量
  │
  ├─④ 提特征                  ONNX Runtime 跑 DINOv2-base
  │     输出 [1, 257, 768]（257 个 token，含 1 个 CLS）
  │     → 沿 token 维平均 → 768 维向量
  │
  └─⑤ L2 归一化               之后余弦相似度 == 向量点积
                              检索时可以直接用矩阵乘，几百只猫一次算完
```

**背景陷阱（这一步最容易被忽略）**：整图提取特征时，模型很容易"记住背景"—— 校园里的猫总在同一块草坪、同一个猫窝前拍照，模型会学到"看到这块草坪 = 这只猫"。一旦有人把照片换到另一个地方拍，识别就崩了。先用检测器把猫框出来再提特征，能显著缓解这个问题。

### 2.3 视频识别的原理

视频没有单独的模型，**本质是"抽帧 → 每张按上面的流程走一遍 → 投票"**：

1. `ffprobe` 读出视频时长
2. 按 `目标帧数 / 时长` 算出抽帧速率（限制在 0.2~4 fps，避免极端值）
3. `ffmpeg -vf fps=<rate> -vframes <n>` 抽出最多 8 帧 JPEG
4. **逐帧提向量后求平均，再重新归一化**

最后一步是关键：视频里猫会转头、会走动、有几帧会糊。把所有帧的向量平均成一个"代表向量"，比挑单独某一帧稳定得多。

> 微信云函数里 **没有 ffmpeg**，这就是自建服务不可替代的最大理由 —— 之前的代码只能用封面帧凑合（`thumbTempFilePath`），现在是真抽帧。

### 2.4 特征库与检索

```
               ┌──────────── sqlite (data/index.sqlite3) ────────────┐
               │  cat_id │ school_id │ dim │ embedding(BLOB) │ ...   │
               └──────────────────────┬──────────────────────────────┘
                                      │ load() 全量载入内存
                                      ▼
  查询向量 q (768,)  ──►  np.stack(bank) → [N, D]  ──►  mat @ q  → [N] 相似度
                                      │
                                      ├─ argsort 取前 Top-5
                                      ├─ 余弦相似度 σ ∈ [-1,1] → 映射成 0~99 展示分
                                      └─ 低于阈值标记 lowConfidence（云函数侧处理）
```

为什么用 sqlite 而不是向量数据库？校园场景几十到几百只猫，每只一条 3KB 向量，全表不到几 MB。**全量载入内存做一次矩阵乘法，比引入一套向量库要快得多也简单得多**——只有当猫数超过几千、或者要做毫秒级检索时才需要 Milvus/pgvector。

分数映射区间定义在 `app/main.py`：

```python
SIM_LOW  = 0.70   # 低于此值得 0 分
SIM_HIGH = 0.96   # 高于此值得 99 分
GAP_CLEAR = 0.03  # Top1 与次名差距小于此值 -> 压低分数，走人工确认
```

> **这两个数字已经用真实猫照片标定过**（`tools/_realcat_probe.py`），不是拍脑袋填的经验值：
>
> | 场景 | 实测余弦相似度 |
> |---|---|
> | 同一只猫 + 旋转/翻转/明暗/模糊 | 0.960 ~ 0.996 |
> | 不同猫之间 | 0.745 ~ 0.926 |
> | 猫 vs 完全无关图片 | 0.509 ~ 0.551 |
>
> 早期版本填的是 `0.40 / 0.85`。**0.85 低于「不同猫」的真实上限 0.926**，结果任意两只猫都打满 99 分，检索完全失效。这正是必须实测标定的原因——不同骨干网络（换 MegaDescriptor / CLIP）的分布不一样，**换模型后请重跑一次标定脚本**。

标定方法（`tools/_realcat_probe.py`，已在联想 Ryzen 7730U 上跑过）：

```bat
..\env\Scripts\python tools\_realcat_probe.py
:: 会打印相似度矩阵，并把建议的 SIM_LOW / SIM_HIGH 算出来
```

除了绝对阈值，还加了一层 **gap 抑制**：Top1 与次名差距小于 `GAP_CLEAR` 时按比例压低分数。因为几只同花色的猫（比如三只橘猫）彼此相似度天然接近，这时给高分等于误导用户点确认——压低之后上层会触发 `lowConfidence`，走人工确认。

### 2.5 关键设计：三级降级

任何一级不可用，服务都照样能起来，只是能力降级：

| 级别 | 触发条件 | 延迟 | 结果可信度 |
|---|---|---|---|
| 1. ONNX Runtime | 配了 `REID_ONNX` 且权重存在 | ~100ms/图 | ✅ 真实可用 |
| 2. PyTorch + timm | 装了 torch/timm（联网拉权重） | 更慢 | ✅ 真实可用 |
| 3. 内置哈希引擎 | 以上都不可用 | 极快 | ⚠️ 演示级，同一张图结果恒定，可用于前后端联调 |

这个设计让你**今天没有模型也能把整条链路调通**，模型准备好后填个环境变量就自动升级，不需要改任何代码。

### 2.6 为什么不用微信自带的 OCR/Vision API

微信官方并不提供"猫个体识别"。可选路径只有三条：接第三方视觉大模型（阿里云/腾讯云/智谱，按次付费且图片要传到对方机房）、端侧模型、或自建。自建的优势是**数据留在自己手里**、长期成本可控，以及能真抽视频帧。

## 四、为什么不用 Docker 也能跑（以及什么时候该用）

Docker 的价值在于"部署环境一致"，但本机伤心的是：

- Docker Desktop 在 Windows 上依赖 WSL2，且会往 C 盘装东西（你 C 盘只剩 29GB）；
- 本地开发调试时，Python venv 启动更快、改代码即刻生效；
- 你是 Windows + 无 GPU，`docker pull` 一个带 CUDA 的镜像毫无意义。

**该用 Docker 的时机**：把服务搬到云主机上线时。那时 `Dockerfile`（已写好，CPU 版 ≈ 400MB）能保证"和本地一模一样"，避免服务器上的依赖地狱。

## 五、一步步跑起来（已在本机验证）

### 步骤 1：创建虚拟环境

```bash
cd E:\Agent\project\stray-animals
E:\Agent\WorkBuddy\binaries\python\versions\3.13.12\python.exe -m venv env
```

### 步骤 2：安装依赖

```bash
env\Scripts\python -m pip install -r server\requirements.txt
env\Scripts\python -m pip install onnxruntime
```

> `requirements.txt` 里已包含 fastapi / uvicorn / numpy / pillow / httpx / python-dotenv。
> **不要**直接装 `torch`——本机无 GPU，装它只为导出权重，白占几百 MB。我们直接下载现成 ONNX。
> 实测本机安装耗时约 4 分钟（网络较慢）。

### 步骤 3：下载 DINOv2 ONNX 权重

```bash
cd server
set HF_ENDPOINT=https://hf-mirror.com
python tools\fetch_model.py
```

产出：`server\models\reid.onnx`（约 90 MB，动态量化版）。

> 为什么是现成 ONNX 而不是 MegaDescriptor？
> `BVRA/MegaDescriptor-*` 在 HF 上**只提供 `pytorch_model.bin`**，要拿到 ONNX 必须先装 torch+timm 再本地导出一次（~1.2GB 下载 + 依赖安装）。
> DINOv2 是 MegaDescriptor 的骨干基础，Xenova 已经帮忙导出好了 ONNX，**下载即用**，性价比高得多。
> 等你确实需要更高精度时再走导出流程（`tools/export_onnx.py` 已备好）。
> 另外：MegaDescriptor 权重是 **CC BY-NC 4.0 禁止商用**，DINOv2 是 Apache-2.0，后续若要商业化没有法律风险。

### 步骤 4：写好 `.env`

项目里已有一份可直接用的 `server\.env`（本机路径已填好）：

```ini
API_TOKEN=catcampus-local-dev-token   # 云函数 AI_TOKEN 必须与此一致
DEVICE=cpu
REID_ONNX=models/reid.onnx
REID_SIZE=224                          # DINOv2 官方分辨率
DETECT_ONNX=                           # 暂无检测权重 → 整图提特征
USE_CLIP=0                             # 属性分类要装 torch，先关
INDEX_DB=data/index.sqlite3
FFMPEG=E:\Agent\project\opc-tools\video-service\ffmpeg\ffmpeg-9.0.1-essentials_build\bin\ffmpeg.exe
FFPROBE=E:\Agent\project\opc-tools\video-service\ffmpeg\ffmpeg-9.0.1-essentials_build\bin\ffprobe.exe
MAX_FRAMES=8
```

**注意**：`.env` 是从**当前工作目录**加载的，所以必须在 `server\` 目录下启动进程，否则相对路径 `models/reid.onnx` 找不到。

### 步骤 5：启动

```bash
cd E:\Agent\project\stray-animals\server
..\env\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8090
```

也可以双击 `server\start.bat`。

### 步骤 6：验证

```bash
curl http://127.0.0.1:8090/health
```

正常返回（模型已就绪时）：

```json
{
  "ok": true,
  "provider": "onnx",     ← 这里必须是 onnx，不是 hash
  "dim": 768,
  "ffmpeg": true,         ← ffmpeg 路径配置成功
  "indexed": 0
}
```

- `provider: hash` → 模型没加载成功，去看启动日志里的 WARNING
- `ffmpeg: false` → FFMPEG 路径不对，视频会退化成封面帧
- `dim: 128` → 说明走的是占位引擎

## 七、接上微信小程序

### 7.1 服务要在公网可访问

本地 `127.0.0.1` 小程序连不到。开发阶段二选一：

- **微信开发者工具 → 详情 → 不校验合法域名**（临时方案，真机预览仍受限）
- **内网穿透**：`cpolar` / `natapp` 开一个隧道，注意必须是 **HTTPS**，且穿透域名要在小程序后台配"request 合法域名"

> 云函数出网访问外部地址**不受小程序 request 域名限制**，所以最终线上环境（服务端有备案域名 + HTTPS）不需要额外配域名。

### 7.2 云函数配两个环境变量

在云开发控制台 → 云函数 `catcampus` → 环境变量：

```
AI_ENDPOINT   = https://你的域名/v1/recognize
AI_TOKEN      = catcampus-local-dev-token     # 与服务端 API_TOKEN 一致
AI_TIMEOUT_MS = 15000
```

配好之后 `lib/vision.js` 会自动走自建服务，不再用占位引擎。**前端零改动。**

### 7.3 视频识别的两种模式

- **同步**（`recognize`）：图片走这条，一次请求等到结果
- **异步**（`recognizeStart` → `recognizePoll`）：视频走这条。云函数先建一条 `ai_tasks` 记录返回 taskId，前端轮询。带 30 秒租约抢占，重复轮询幂等，不会重复烧调用

### 7.4 触发建库

新猫入册后要跑一次建库才能被识别到。管理员在工作台点一下（action 已就绪 `buildAiIndex`），或直接：

```bash
curl -X POST http://127.0.0.1:8090/v1/index/build \
  -H "Authorization: Bearer catcampus-local-dev-token" \
  -H "Content-Type: application/json" \
  -d '{"schoolId":"sch_xxx","cats":[{"id":"cat_1","name":"橘座","photos":["https://临时链接/a.jpg","https://临时链接/b.jpg"]}]}'
```

多张照片平均出的"代表向量"比单张稳很多，建议每只猫传 3~6 张不同角度的照。

## 八、常见故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `provider: hash` | 模型文件路径错 / 下载不完整 | 确认在 `server\` 目录启动；检查 `models\reid.onnx` 大小是否正常（约 90MB） |
| `ffmpeg: false` | 环境变量未加载或路径错 | `.env` 里用绝对路径；路径含反斜杠要照抄原样 |
| 候选列表为空 | 该校特征库没建 | 先调 `/v1/index/build`；看 `/health` 的 `indexed` 是否 > 0 |
| 首帧就失败 502 | 素材 URL 下载不了 | **微信云存储的 `cloud://fileId` 外网下载不了**，必须先换临时 HTTPS 链接（云函数里 `attachTempUrls()` 已处理） |
| pip 装包超时 | 网络慢 | 加 `--timeout 60`；或换清华源 `-i https://pypi.tuna.tsinghua.edu.cn/simple` |
| HF 下载 403/连不上 | huggingface.co 被墙 | 设置 `HF_ENDPOINT=https://hf-mirror.com` |
| 识别分数都很低 | 未校准阈值 | 用真实照片调整 `main.py` 的 `SIM_LOW` / `SIM_HIGH` |

| 阶段 | 配置 | 适用规模 |

| **现在** | DINOv2-base 量化 ONNX + 整图 | < 30 只猫，CPU 单图 ~100ms |
| **下一步** | + YOLOv8n 检测框（填 `DETECT_ONNX`） | 明显降低背景误判 |
| **中期** | 换 DINOv2-large 或用 `export_onnx.py` 导出 MegaDescriptor | 30~100 只猫 |
| **远期** | 猫数 > 100 且同类猫总认混 → 用攒下的 `ai_samples` 做微调 | 才真正开始"训练" |

> 每次用户点"确认猫身份"，云函数都会往 `ai_samples` 写一条样本。用得越久，将来微调需要的训练集自动就攒出来了 —— 这是个飞轮，不必一开始就为训练发愁。
