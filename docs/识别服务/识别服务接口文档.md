# 喵园 CatCampus 识别服务 · 接口文档

> 服务代码：`server/`（FastAPI + ONNX Runtime），对外提供「图片 / 视频猫脸识别 + 特征库检索」。  
> 本文档与 `server/app/main.py` 逐字段对齐，可作为前端 / 后端 / 云函数对接的唯一依据。

---

## 1. 基础约定

### 1.1 服务地址

| 环境                 | 地址                                                        |
| ------------------ | --------------------------------------------------------- |
| 本地调试               | `http://127.0.0.1:8090`                                   |
| 云托管（CloudBase Run） | 平台分配的公网域名（如 `https://xxx.ap-shanghai.run.tcloudbase.com`） |

### 1.2 鉴权

除 `GET /health` 外，所有接口都要鉴权。请求头：

```
Authorization: Bearer <API_TOKEN>
```

- `API_TOKEN` 来自服务端环境变量，须与调用方（后端 `catcampus.vision.token` / 云函数 `AI_TOKEN`）**完全一致**。
- 若服务端 `API_TOKEN` 未配置（空），则所有接口对内网开放（仅调试用，生产务必设 token）。
- 鉴权失败返回 `401 invalid token`。

### 1.3 通用数据类型

- **CatRef（候选猫档案）**：识别 / 建库时由调用方带来，用于把「向量」映射回「猫」。
  | 字段        | 类型       | 说明                                                                       |
  | --------- | -------- | ------------------------------------------------------------------------ |
  | `id`      | string   | 猫的唯一标识（建议用后端猫ID），**建库后作为特征库主键**                                          |
  | `name`    | string   | 展示名，识别结果回显用                                                              |
  | `pattern` | string   | 花纹（辅助标签，如 tabby/solid），回显用                                               |
  | `color`   | string   | 毛色（辅助标签），回显用                                                             |
  | `photos`  | string[] | **可直接下载的绝对 URL 列表**（http/https）。识别服务在另一台机器时需公网/内网可达，不能是 `127.0.0.1` 指向自己 |
- **schoolId（校区隔离）**：留空表示全局库；多校区部署时传不同值，特征库与检索互不干扰。

### 1.4 状态码约定

| HTTP | 含义                                |
| ---- | --------------------------------- |
| 200  | 成功                                |
| 400  | 参数错误（如识别请求既无 `url` 也无 `videoUrl`） |
| 401  | token 无效                          |
| 413  | 上传图片超过 `MAX_IMAGE_BYTES`（仅 `/v1/photo/standard` 的原始图片请求体） |
| 502  | 素材下载失败（图片/视频 URL 不可达或解码失败）/ 外部生图服务失败 |
| 503  | 服务未配置（如缺少 `API_TOKEN`，或标准照接口的 `IMAGE_GEN_URL` 与 `AGNES_API_KEY` 都为空） |
| 5xx  | 模型加载 / 推理异常（看服务端日志）               |

## 2. 接口清单

| 方法     | 路径                | 鉴权 | 作用                        |
| ------ | ----------------- | -- | ------------------------- |
| GET    | `/health`         | 否  | 健康检查 + 引擎信息               |
| POST   | `/v1/recognize`   | 是  | **核心：识别一张图 / 一段视频，返回候选猫** |
| POST   | `/v1/embed`       | 是  | 单独抽一张图的向量（调试 / 建库脚本用）     |
| POST   | `/v1/index/build` | 是  | 批量把猫档案照片建成特征库             |
| GET    | `/v1/index/ids`   | 是  | 列出特征库里真实存在的猫 id（管理端核对用）  |
| DELETE | `/v1/index`       | 是  | 清空特征库（整体重建前调用）            |
| POST   | `/v1/matting`     | 是  | **一键抠图**：输出透明底/纯色底 PNG    |
| POST   | `/v1/portrait`    | 是  | **大头照**：猫头特写圆形徽章 PNG     |
| POST   | `/v1/album`       | 是  | **相册拼图**：多猫抠图马卡龙网格 PNG    |
| POST   | `/v1/photo/standard` | 是 | **AI 标准照**：一张猫照 → 全身 + 正面两张 PNG |

> `matting` / `portrait` / `album` 是「创意图像」接口（2026-10-31 新增）：与识别链路
> 共用检测 + 抠图模型，但**不走质量门控** —— 创意场景要的是「给我一张图」，
> 诊断字段由前端决定是否提示。
>
> `photo/standard` 是 AIGC 生成接口（2026-10-31 新增）：花色识别 → 两组提示词 →
> 外部图片生成服务。默认走 agnes 图片模型（**带原图参考图 i2i**，生成的是同一只猫）；
> 也可用 `IMAGE_GEN_URL` 接其它服务商（仅提示词）。两者都未配置则返回 503（见 3.10）。

## 3. 接口详解

### 3.1 `GET /health`

健康检查。部署后第一步先打这个，确认模型加载、ffmpeg 可用、特征库猫数。

**请求参数（query）**：`schoolId`（可选）—— 传了则 `index.count` 只统计该校，`index.total` 恒为全库。

**响应结构**：按**排查维度分组**（2026-10-31 重构，替代原来 20 多个平铺字段）。
每组对应一类「识别不准」的成因，哪一组不对就查哪一块。

| 分组      | 字段                         | 类型     | 说明                                          |
| ------- | -------------------------- | ------ | ------------------------------------------- |
| —       | `ok`                       | bool   | 恒为 true                                      |
| `model` | `backend`                  | string | 特征引擎后端：`onnx` / `torch` / `hash`             |
|         | `file`                     | string | 实际加载的权重文件名（如 `mega_descriptor_t.onnx`）       |
|         | `dim`                      | int    | 向量维度（MegaDescriptor-T = 768）                 |
|         | `inputSize`                | int    | 模型实际接受的输入边长（可能与配置不同，按模型探测）                  |
|         | `norm`                     | string | 归一化口径：`half`（MegaDescriptor）/ `imagenet`      |
|         | `poolVersion`              | int    | 特征算法版本（`FEATURE_POOL_VERSION`），库里只有同版本向量参与检索 |
| `detect`| `enabled`                  | bool   | 猫体检测是否启用（false = 整图提特征，背景污染向量）             |
|         | `file`                     | string | 检测权重文件名（如 `yolov8n.onnx`）                    |
|         | `inputSize`                | int    | 检测输入边长                                      |
|         | `conf` / `pad`             | float  | 置信阈值 / 框外扩比例                                 |
| `attr`  | `enabled`                  | bool   | **仅表示 CLIP 是否开启**；为 false 时花色仍由启发式给出        |
|         | `source`                   | string | 花色实际来源：`clip` / `api` / `heuristic`          |
|         | `rerank`                   | bool   | 花色是否参与候选重排                                  |
| `match` | `minSim`                   | float  | 最低相似度（低于则不返回候选）                             |
|         | `identifyMin`              | int    | 判定「识别成功」的最低展示分                              |
|         | `simMid` / `simSlope`      | float  | 校准曲线中点 / 斜率（`SIM_MID` 越大越严格）                |
| `media` | `framesMax`                | int    | 视频抽帧上限                                      |
|         | `ffmpeg`                   | bool   | 是否检测到 ffmpeg（影响视频抽帧）                        |
| `cache` | `cached`                   | int    | 识别结果缓存条数                                    |
|         | `computing`                | int    | 正在计算的条数                                     |
| `index` | `count`                    | int    | 特征库猫数（传 `schoolId` 时按校）；`-1` = 读取失败          |
|         | `total`                    | int    | 全库猫数（含其它学校 + 已删档案残留）                        |
|         | `scoped`                   | bool   | `count` 是否按校过滤                              |
|         | `backend`                  | string | 特征库后端：`sqlite_store` / `cos_store`           |
|         | `error`                    | string | 后端异常原因；正常时为空串                               |

**示例**：

```json
{
  "ok": true,
  "model": { "backend": "onnx", "file": "mega_descriptor_t.onnx", "dim": 768,
             "inputSize": 224, "norm": "half", "poolVersion": 4 },
  "detect": { "enabled": true, "file": "yolov8n.onnx", "inputSize": 640,
              "conf": 0.35, "pad": 0.08 },
  "attr": { "enabled": false, "source": "heuristic", "rerank": false },
  "match": { "minSim": 0.30, "identifyMin": 45, "simMid": 0.42, "simSlope": 25.0 },
  "media": { "framesMax": 8, "ffmpeg": true },
  "cache": { "cached": 0, "computing": 0 },
  "index": { "count": 7, "total": 11, "scoped": true,
             "backend": "sqlite_store", "error": "" }
}
```

> 云函数侧仍按旧的平铺字段对外输出（`indexed` / `indexedTotal` / `attrSource` …），
> 由 `vision.js` 做一层摊平映射，管理端无需改动。

### 3.2 `POST /v1/recognize` ⭐

**核心接口**。输入一张图片或一个视频，返回特征标签 + 候选猫排序。

#### 请求体（`RecognizeReq`）

| 字段         | 类型       | 必填  | 说明                               |
| ---------- | -------- | --- | -------------------------------- |
| `url`      | string   | 二选一 | 图片可下载 URL（图片识别走这条）               |
| `thumbUrl` | string   | 否   | 主图缩略图 URL。**2026-10-28 新增**：云函数换临时链接时用 `imageMogr2/thumbnail/768x` 现拼，识别服务优先下载它（ReID 输入才 518px，768px 足够），原图常 3~10MB、跨服务出网下载要十几秒。下载失败（缩略参数不支持 / 链接过期）自动回退 `url`，且不进缓存键。视频不传此项 |
| `videoUrl` | string   | 二选一 | 视频可下载 URL（配合 `type:"video"` 走抽帧） |
| `fileId`   | string   | 否   | 预留字段，当前未启用（微信云存储 fileId 需先换临时链接） |
| `type`     | string   | 否   | `image`（默认）或 `video`             |
| `frames`   | int      | 否   | 视频抽帧数，默认 1，上限 8（`MAX_FRAMES`）    |
| `schoolId` | string   | 否   | 校区隔离，留空=全局库                      |
| `cats`     | CatRef[] | 否   | 候选猫档案。识别服务特征库为空时会用这里的照片**冷启动补库** |
| `waitMs`   | int      | 否   | **缓存排队耐心（毫秒）**。同一个素材已有一次计算在跑时，本次最多等它多久；等不到立即返回 `503 识别排队中`。云函数按自己的 AI 窗口填（poll 路径约 1.5s）。 |

> `waitMs` 是为视频识别准备的：视频服务端约 3.5s，而云函数 poll 路径只能给 AI 1.8s
> （客户端 `callFunction` 约 3s 的硬预算决定，放大不了）。窗口注定算不完，
> 所以策略不是硬等，而是「第一次算完写缓存，第二次直接取」——
> `waitMs` 保证后来者排队等第一次的结果，而不是各算各的。
> 缺了它，同一个视频会被反复计算（线上实测 1 分钟 10 次），且每次结果都被丢弃。

> 注：`url` 与 `videoUrl` 至少传一个，否则 `400`。

#### 响应字段

**`features`（本张图提的特征）**：

| 字段           | 类型       | 说明                                                                                |
| ------------ | -------- | --------------------------------------------------------------------------------- |
| `tags`       | object[] | 标签卡：`[{k:"毛色",v:"橘猫"},{k:"花纹",v:"tabby"},{k:"检测",v:"已定位猫体"/"整图"},{k:"帧数",v:"3"}]` |
| `pattern`    | string   | 花纹（CLIP 零样本分类，辅助展示）                                                               |
| `color`      | string   | 毛色（同上）                                                                            |
| `size`       | string   | 预留，当前恒空                                                                           |
| `confidence` | float    | 属性分类置信度（无 CLIP 时回退 0.75）                                                          |
| `embedding`  | float[]  | 查询向量（已 L2 归一化，维度 = `dim`）                                                         |

**`candidates`（候选猫，按相似度降序，最多 2 个，`config.TOP_N`）**：

> 只给 Top-2（2026-10-25 起）。第 3 名往后的余弦已贴着 `MIN_SIM` 匹配线，
> 展示分是个位数 —— 用户看到「3% 的可能是它」得不到任何信息，
> 而且候选越多 Top1 的领先幅度（`lead`）越被稀释，排查时更难看。
> 想临时放大到 5 条观察候选分布：设环境变量 `TOP_N=5`。

| 字段       | 类型     | 说明                                           |
| -------- | ------ | -------------------------------------------- |
| `catId`  | string | 匹配到的猫 ID（来自 `cats[].id`）                     |
| `name`   | string | 猫名（来自 `cats[].name`）                         |
| `avatar` | string | 首图 URL（来自 `cats[].photos[0]`）                |
| `score`  | int    | **0~99 展示分**，余弦经 logistic 校准（`SIM_MID`/`SIM_SLOPE`） |
| `rawSim` | float  | 真实余弦相似度（0~1，保留 4 位）                          |
| `lead`   | float  | 仅 Top1：领先次名的余弦差（无次名时不出现）                    |
| `attrMatch` | bool? | 仅当本次判出了花色：`true` 相容 / `false` 冲突 / 缺省=无从判断（诊断用） |
| `scoreCapped` | bool? | 仅当档案花色为空、本次又判出了花色：`score` 被 `ATTR_UNKNOWN_CAP`（默认 60）封顶，`rawSim` 不受影响（诊断用） |
| `reason` | string | 文案，如「特征相似度 76.3%」                            |

> **两个分数不是一回事，别混着看**：`score` 是余弦经 **logistic 校准**后的「把握」，
> `rawSim` 是原始余弦。旧版是 0.75~0.90 线性拉伸，实测把「同一只猫的另一张照片」
> （余弦 0.763）压成 9 分并判定「没认出来」，2026-10-24 已换成 logistic。
> 参数随骨干重标定：**MegaDescriptor（当前）** `SIM_MID=0.42 / SIM_SLOPE=25`，
> 参照点 `0.364→20 / 0.408→42 / 0.431→56 / 0.488→84 / 0.556→96 / 0.667→99`；
> 历史 DINOv2 为 `SIM_MID=0.755 / SIM_SLOPE=30`（`0.62→1 / 0.74→39 / 0.763→55`）。
> `IDENTIFY_MIN=45` 在当前曲线对应余弦 **≈0.413**。
> 候选档案的花色为空、而本次判出了花色时，色彩这一维无从校验，`score` 会被
> `ATTR_UNKNOWN_CAP`（默认 60）封顶（条目带 `scoreCapped`），`rawSim` 保持真实余弦 ——
> 避免「档案没填花色」的候选被显示成 90+ 的确定匹配（2026-10-31 现场）。
> 云函数下发前会用 `candidateReason()` 把 `reason` 改写成能自洽的说明
> （「原始相似度 100.0% · 展示分封顶 99」/「原始相似度 76.3% · 领先次名 6.5%」/「… · 低于匹配线」）。

**`meta`（元数据）**：

| 字段         | 类型     | 说明        |
| ---------- | ------ | --------- |
| `provider` | string | 引擎后端      |
| `frames`   | int    | 实际参与推理的帧数 |
| `qualityOk` | bool  | **质量门控**（2026-10-26 起）：查询图是否通过「占比 + 低光」双维校验。不通过时不出候选、花色弃权（前端走「这张照片没法比对」） |
| `qualityReason` | string | 未通过原因：`area_too_small`（猫占比过小）/ `too_dark`（光线太暗，请靠近光源重拍）/ 空串（通过）。排查见 `识别不准排查手册.md` 八之五 |
| `areaRatio` | float | 猫体占画面短边比例，低于 `QG_MIN_AREA_RATIO=0.06` 拦（约猫占画面 1/4 以内随手拍） |
| `lightMeanV` | int/null | 猫体 crop 平均亮度 V（0~255）。低于 `QG_MIN_LIGHT_MEAN_V=125` 拦（夜间 105/113 vs 白天 ≥178）；夜间近拍白猫误判黑猫即被此门控拦下 |
| `qualityArea` | bool | 占比门控是否通过（与 `qualityOk` 配套，便于前端分维度提示） |
| `latency`  | int    | 端到端耗时（毫秒）。**缓存命中时是首次计算的耗时**，不是本次 |
| `cached`   | bool   | 本次结果是否来自缓存（2026-10-25 起）。视频场景第二轮轮询应为 `true` |
| `waitMs`   | int    | 仅缓存命中时：本次排队等前一次计算花了多少毫秒 |
| `indexed`  | int    | 检索时特征库猫数  |
| `attrSource` | string | 花色实际来源：`clip` / `api` / `heuristic` / 空 |
| `attrReason` | string | 花色判不出/多帧不一致时的原因，空 = 正常结论。2026-11-05 起也包含**照片不可用**（偏模糊 / 几乎找不到猫体）的拒识文案，可直接作为「请重拍」提示展示 |
| `attrShift`  | float | 曝光自适应平移量（正常 ±45 内；剧烈波动 = 画面曝光异常，2026-10-25 起） |
| `attrFrames` | int   | 多帧聚合实际采用的启发式帧数（视频 >1；纯 CLIP 帧为 0） |

### 3.3 `POST /v1/embed`

单独抽一张图的向量，用于建库脚本 / 调试，不经过检索。

**请求体（`EmbedReq`）**：

| 字段       | 类型     | 必填 | 说明                  |
| -------- | ------ | -- | ------------------- |
| `url`    | string | 是  | 图片 URL              |
| `detect` | bool   | 否  | 是否先用检测模型裁猫（默认 true） |

**响应**：

```json
{ "embedding": [0.01, -0.03, "…"], "dim": 768,
  "color": "橘猫", "pattern": "tabby", "detected": true }
```

---

### 3.4 `POST /v1/index/build`

**批量建库**：把档案里每只猫的多张照片平均成一个「代表向量」存入特征库。多张平均比单张稳（正面/侧面/光线差异被抹平）。

**请求体（`BuildReq`）**：

| 字段             | 类型       | 必填 | 说明                                     |
| -------------- | -------- | -- | -------------------------------------- |
| `schoolId`     | string   | 否  | 校区隔离                                   |
| `cats`         | CatRef[] | 是  | 要建库的猫（每只取 `photos` 前 `photosPerCat` 张） |
| `photosPerCat` | int      | 否  | 每猫取几张，默认 6                             |

**响应**：

| 字段        | 类型                     | 说明                                     |
| --------- | ---------------------- | -------------------------------------- |
| `ok`      | bool                   |                                        |
| `built`   | int                    | 成功建库猫数                                 |
| `failed`  | string[]               | 建库失败的猫 ID                              |
| `skipped` | int                    | `onlyMissing` 且库里已有向量而跳过的猫数            |
| `reasons` | object&lt;string,string&gt; | **失败原因**（键=猫 ID）：`noPhoto` / `downloadFailed:2/3` / `noVector:1/3` / `embedFailed:xxx` |
| `total`   | int                    | 建库后特征库猫数                               |

> `reasons` 是给管理端看的诊断，不是调试附赠品：建库失败在云函数侧只表现为「`built=0`」，
> 管理页以前只能提示「请稍后重试」，真实成因（照片没换出链接 / 下载失败 / 编码抛错）全被吞掉，
> 管理员只能反复点按钮。现在每只失败的猫都带一条原因，前端直接显示。
>
> `downloadFailed:a/b` 表示服务端下载了 `b` 张、`a` 张失败 —— 对应日志里 `下载失败 <url>：<异常>`。

**示例**：

```bash
curl -X POST http://127.0.0.1:8090/v1/index/build \
  -H "Authorization: Bearer catcampus-local-dev-token" \
  -H "Content-Type: application/json" \
  -d '{"schoolId":"","photosPerCat":4,
       "cats":[{"id":"3","name":"小橘","photos":["http://.../o1.jpg","http://.../o2.jpg"]}]}'
```

```json
{ "ok": true, "built": 1, "failed": [], "skipped": 0, "reasons": {}, "total": 13 }
```

### 3.5 `GET /v1/index/ids`

列出特征库里**真实存在**的猫 id。管理端「哪些档案还没录入」必须查这里，不能信云库的 `cats.aiIndexAt`（那只是云函数侧的乐观记账，服务端补库失败时它照样有值）。

**请求参数（query）**：

| 参数         | 类型     | 说明                 |
| ---------- | ------ | ------------------ |
| `schoolId` | string | 留空查全库；否则只查该校区     |

**响应**：

```json
{ "ok": true, "ids": ["3", "7", "12"], "total": 3, "backend": "sqlite" }
```

特征库读不出来时返回 `503`，让管理端明确显示「查不到」，而不是空列表被误读成「一只都没入库」。

### 3.6 `DELETE /v1/index`

**清空特征库**，整体重建前调用。配合 `/v1/index/build` 实现「档案库即真相来源」——增删改猫后整体同步一次即完全一致。

**请求参数（query）**：

| 参数         | 类型     | 说明                        |
| ---------- | ------ | ------------------------- |
| `schoolId` | string | 留空清全部；否则只清该校区            |
| `catId`    | string | 传了则**只删这一只**（删除猫档案时调用，2026-10-25 起） |

**响应**：

```json
{ "ok": true, "scope": "school", "removed": 13, "remaining": 0 }
```

> 删档案不删向量会留「幽灵向量」：检索时仍被返回，管理页「N 条向量」对不上档案数。
> 所以删除猫档案的下游必须带上 `catId` 调一次本接口。

### 3.7 `POST /v1/matting` ⭐（创意）

**一键抠图**。输入一张图，输出抠好主体的 PNG（base64）。典型用法：用户上传猫照 → 云函数转发 → 透明底 PNG 落云存储，做表情包/海报素材。

**请求体（`MattingReq`）**：

| 字段            | 类型     | 必填  | 说明                                             |
| ------------- | ------ | --- | ---------------------------------------------- |
| `url`         | string | 二选一 | 图片可下载 URL                                       |
| `imageBase64` | string | 二选一 | 内联图片（base64 / data URL），优先于 `url`，省一次跨服务下载      |
| `bg`          | string | 否   | 背景：`transparent`（默认，RGBA 透明底）/ `gray`（识别链路口径灰底）/ `#RRGGBB`（任意纯色底） |

**响应字段**：

| 字段            | 类型     | 说明                                                   |
| ------------- | ------ | ---------------------------------------------------- |
| `ok`          | bool   |                                                      |
| `mime`        | string | 恒 `image/png`                                         |
| `image`       | string | PNG 的 base64（无前缀）。小程序端 `wx.base64ToArrayBuffer` 后写临时文件 |
| `matted`      | bool   | 抠图是否成功（false = 模型没产生有效前景，返回的是原图）                     |
| `box`         | int[]  | 主体掩膜外接框 `[x1,y1,x2,y2]`（原图坐标），仅 `matted=true` 时出现    |
| `coverage`    | float  | 前景像素占比（0~1）                                          |
| `tight`       | float  | 掩膜外接框相对画面的紧凑度                                        |
| `lowCoverage` | bool   | **抠图翻车预警**：`coverage < MATTING_MIN_COVERAGE(0.10)` 时为 true —— 主体大概率被抠没了（提亮后的白猫是典型现场），前端应提示换图 |

**示例**：

```bash
curl -X POST http://127.0.0.1:8090/v1/matting \
  -H "Authorization: Bearer $API_TOKEN" -H "Content-Type: application/json" \
  -d '{"url":"https://.../cat.jpg","bg":"transparent"}'
```

```json
{ "ok": true, "mime": "image/png", "image": "iVBORw0KG…(base64)…",
  "matted": true, "box": [122, 205, 1929, 1684], "coverage": 0.3025,
  "tight": 0.6713, "lowCoverage": false }
```

### 3.8 `POST /v1/portrait`（创意）

**大头照**。检测猫 → 掩膜顶部像素（耳朵区）质心定位头部 → 正方形裁剪 → 圆形徽章底（透明四角），输出头像 PNG。

**请求体（`PortraitReq`）**：

| 字段            | 类型     | 必填  | 说明                                |
| ------------- | ------ | --- | --------------------------------- |
| `url`         | string | 二选一 | 图片 URL                            |
| `imageBase64` | string | 二选一 | 内联图片                              |
| `size`        | int    | 否   | 输出边长（px），默认 512，钳制在 128~1024     |
| `bg`          | string | 否   | 徽章底色 `#RRGGBB`，默认浅蓝 `#D6EAF8`     |

**响应**：在 `/v1/matting` 的字段基础上多两个：

| 字段         | 类型   | 说明                                                  |
| ---------- | ---- | --------------------------------------------------- |
| `detected` | bool | 检测模型是否框到猫。false = 退化为「整图上半部居中截」，前端可提示「没找到猫，帮你整图截了一张」 |
| `size`     | int  | 实际输出边长                                              |

**示例**：

```json
{ "ok": true, "mime": "image/png", "image": "iVBOR…",
  "matted": true, "coverage": 0.3025, "detected": true, "size": 512 }
```

### 3.9 `POST /v1/album`（创意）

**相册拼图**。多张猫照抠图后拼成马卡龙底网格图（底部带名字条）。最多 **9 张**（3×3；更多格子在手机上只剩 100 多像素，看不清脸）。

**请求体（`AlbumReq`）**：

| 字段                  | 类型         | 必填 | 说明                            |
| ------------------- | ---------- | -- | ----------------------------- |
| `items`             | object[]   | 是  | 每张 `{url?, imageBase64?, name?}`，二者至少传一个；`name` 为空不画名字条 |
| `items[].url`       | string     | 二选一 | 图片 URL                        |
| `items[].imageBase64` | string   | 二选一 | 内联图片                          |
| `items[].name`      | string     | 否  | 格子底部名字条（容器无中文字体时自动跳过，不崩）      |
| `cols`              | int        | 否  | 列数。0 = 自动（≤4 张 2 列，否则 3 列）    |

**响应**：

| 字段              | 类型     | 说明                                     |
| --------------- | ------ | -------------------------------------- |
| `image`         | string | 拼图 PNG base64                           |
| `count`         | int    | 实际拼入张数（下载失败的自动跳过）                      |
| `cols` / `rows` | int    | 网格行列                                   |
| `matted`        | int    | 抠图成功张数                                 |
| `unmatttedIdx`  | int[]  | 抠图失败退化为原图贴入的格子下标（**不缺席**：纪念场景完整性 > 精致度） |
| `width`/`height` | int   | 输出图尺寸（px）                              |

**示例**：

```bash
curl -X POST http://127.0.0.1:8090/v1/album \
  -H "Authorization: Bearer $API_TOKEN" -H "Content-Type: application/json" \
  -d '{"items":[{"url":"https://.../a.jpg","name":"小橘"},
                 {"url":"https://.../b.jpg","name":"煤球"}]}'
```

```json
{ "ok": true, "mime": "image/png", "image": "iVBOR…",
  "count": 2, "cols": 2, "rows": 1, "matted": 2, "unmatttedIdx": [],
  "width": 1114, "height": 640 }
```

> 三个创意接口都支持「先 base64 后 URL」的取图顺序，错误码与识别接口一致
> （`400` 参数错 / `401` 鉴权 / `502` 素材下载失败 / `500` 推理异常）。

### 3.10 `POST /v1/photo/standard` ⭐（AIGC 生成）

**猫咪标准照**。上传一张猫照，返回两张 AI 生成的标准写真：

| 序号 | 文件名 | 内容 | 默认画幅 |
| -- | -- | -- | -- |
| 1 | `<name>1.png` | **全身站姿照**（自然站立、完整全身） | `2048x1536` |
| 2 | `<name>2.png` | **正面标准照**（对焦面部、证件肖像感） | `2048x2048` |

链路：取图 → 属性分析（未传 `animal` 时识别花色/品种）→ 按「动物标准写真生成器」
拼两组提示词（含防肢体崩坏/畸形耳朵等约束）→ 生成两张 → PNG base64。

**生成后端**（默认 agnes 图片模型，带参考图）：

- 不配 `IMAGE_GEN_URL` 时走 agnes（`AGNES_API_KEY` + `IMAGE_GEN_MODEL`）：
  请求体里带原图的 `image`（data URI）字段，服务端走 **i2i 队列**，
  生成的猫保持输入照片的毛色分布、花纹位置、眼色、脸型与体型，**不是同品种的陌生猫**。
  提示词会自动加上「以参考照片中的同一只猫为主体…不要换成另一只猫」的约束。
- 配置了 `IMAGE_GEN_URL` 时走该模板（只能传提示词、无参考图），用于接其它服务商。

**请求方式**（两种等价）：

1. JSON（与其它接口一致，`imageBase64` 优先于 `url`）
2. **直接把图片字节作为请求体**，`Content-Type: image/*`，其余参数放 query string
   （即字面意义的「上传一张照片」；不需要 `python-multipart`）

| 字段 | 类型 | 必填 | 说明 |
| -- | -- | -- | -- |
| `url` | string | 二选一 | 图片可下载 URL |
| `imageBase64` | string | 二选一 | 内联图片（base64 / data URL），优先于 `url` |
| `animal` | string | 否 | 猫名/花色（三花猫、玄猫、奶牛猫…）。空 = 自动识别并写入提示词 |
| `style` | string | 否 | 画面风格，默认「写实高清摄影」 |
| `extra` | string | 否 | 额外要求（背景/光影/画质等） |
| `name` | string | 否 | 输出文件名前缀，默认用 `animal`，最终为 `<name>1.png` / `<name>2.png` |
| `save` | bool | 否 | 是否落盘到 `IMAGE_GEN_DIR`。true 且未配目录 → 502 |

**响应字段**：

| 字段 | 类型 | 说明 |
| -- | -- | -- |
| `ok` | bool | 恒 true（失败走 4xx/5xx） |
| `animal` | string | 实际写进提示词的花色/品种（`animalSource=request` 时取自入参） |
| `animalSource` | string | `request`（入参指定）/ `auto`（属性分析） |
| `detected` | bool | 自动分析时是否框到猫（false 时 animal 可能退化为「猫」） |
| `attr` | object | 自动分析结果：`color/pattern/breed/confidence/source/reason` |
| `provider` | string | 实际使用的生成后端：`agnes`（带参考图 i2i）/ `url`（IMAGE_GEN_URL 模板） |
| `reference` | bool | 是否把原图作为参考图发给生成服务（true = 保证「同一只猫」） |
| `images[].kind` | string | `fullBody`（xx1）/ `front`（xx2） |
| `images[].label` | string | 中文名：全身站姿照 / 正面标准照 |
| `images[].filename` | string | 建议文件名（`<name>1.png` / `<name>2.png`） |
| `images[].imageSize` | string | 实际下发给服务商的画幅 |
| `images[].prompt` | string | 实际使用的提示词（排查生成效果时先看它） |
| `images[].image` | string | PNG base64（无前缀） |
| `images[].path` | string | 仅 `save=true`：落盘的绝对路径 |
| `latency` | int | 总耗时（ms，含两次远端生成） |

**示例**：

```bash
# 方式一：JSON
curl -X POST http://127.0.0.1:8090/v1/photo/standard \
  -H "Authorization: Bearer $API_TOKEN" -H "Content-Type: application/json" \
-d '{"url":"https://.../cat.jpg","name":"三花猫"}'

# 方式二：直接上传图片字节
curl -X POST "http://127.0.0.1:8090/v1/photo/standard?name=三花猫" \
  -H "Authorization: Bearer $API_TOKEN" -H "Content-Type: image/jpeg" \
  --data-binary @三花猫.jpg
```

```json
{ "ok": true, "animal": "三花猫", "animalSource": "auto", "detected": true,
  "provider": "agnes", "reference": true,
  "images": [
    { "kind": "fullBody", "label": "全身站姿照", "filename": "三花猫1.png",
      "imageSize": "2048x1536", "prompt": "……", "image": "iVBOR…" },
    { "kind": "front", "label": "正面标准照", "filename": "三花猫2.png",
      "imageSize": "2048x2048", "prompt": "……", "image": "iVBOR…" }
  ],
  "latency": 76424 }
```

**错误码**：

| HTTP | 含义 |
| -- | -- |
| 400 | 请求体既不是 JSON 也不是图片 / JSON 参数错误 |
| 413 | 图片超过 `MAX_IMAGE_BYTES` |
| 502 | 素材下载失败 / 生图服务失败（非 200、返回非图片、无图片字段） |
| 503 | **两种生成后端都未配置**（`IMAGE_GEN_URL` 与 `AGNES_API_KEY` 均为空），不会用本地拼图伪造生成结果 |

**配置**（`server/.env`）：

| 变量 | 默认 | 说明 |
| -- | -- | -- |
| `IMAGE_GEN_URL` | 空 | 其它服务商的请求模板，支持 `{prompt}` / `{image_size}`；**只能传提示词、无参考图**。留空则走 agnes |
| `IMAGE_GEN_TOKEN` | 空 | 可选 `Authorization: Bearer <token>`（仅模板后端） |
| `IMAGE_GEN_MODEL` | `agnes-image-2.1-flash` | agnes 图片模型；带 `image` 字段即 i2i（带参考图） |
| `IMAGE_GEN_TIMEOUT` | 120 | 单张生成超时（秒） |
| `IMAGE_GEN_MAX_BYTES` | 20971520 | 远端返回图片 URL 时的下载上限 |
| `IMAGE_GEN_SIZE_FULL` / `IMAGE_GEN_SIZE_FRONT` | `2048x1536` / `2048x2048` | 两张图的画幅。只接受 `1K/2K/3K/4K` 或 `WIDTHxHEIGHT`，`landscape_4_3` 这类命名会被 agnes 400 |
| `IMAGE_GEN_DIR` | 空 | `save=true` 时的落盘目录；留空只返回 base64 |

> i2i 队列对横版输出有上限：实测请求 `2048x1536` 实际返回 `1152x864`（方图按请求输出）。
> `images[].imageSize` 是**请求值**，实际像素以返回图为准。

## 4. 典型调用流程

### 4.1 首次上线 / 新增猫后同步特征库

```
DELETE /v1/index            # 清空旧库（整体重建）
POST   /v1/index/build      # 用猫档案重建（后端「同步特征库」按钮即这两步）
```

### 4.2 识别一张用户上传的图

```
POST /v1/recognize { url, cats:[当前全部猫档案] }
  → 前端展示 candidates 里 score 最高的猫；score 低则提示「未匹配到，可人工确认」
```

> 特征库为空时，`recognize` 会用请求里的 `cats[].photos` 冷启动补库（限流 40 只/次），跑过一次 build 后基本不走这条。

### 4.3 创意图像：给猫生成头像 / 相册

```
POST /v1/portrait { imageBase64 }          # 单只猫 → 圆形徽章头像
  → detected=false 时前端提示「没找到猫，帮你整图截了一张」

POST /v1/album { items:[{url,name},…] }    # 多只猫 → 马卡龙网格相册
  → unmatttedIdx 非空时前端可提示「第 N 张抠图失败，已用原图」
```

> 三个创意接口的图都走「base64 优先、URL 兜底」，云函数把缩略图下到内存后内联转发，
> 可省一次服务端出网下载（识别链路同策略）。

```
POST /v1/photo/standard { imageBase64, name:"三花猫" }   # 一张 → 两张 AI 标准照
  → 返回 images[0]=三花猫1.png（全身站姿）、images[1]=三花猫2.png（正面标准）
```

## 5. 对接方须知（后端 / 云函数）

- **后端 `VisionService`**：代理 `/v1/recognize` 与 `/v1/index/build`，负责把后端相对路径 photos 补成识别服务可达的绝对 URL（配置 `catcampus.vision.asset-base-url`）。
- **云函数 `lib/vision.js`**：契约一致的旧版调用，切换为调用本服务时只需改 `AI_ENDPOINT` / `AI_TOKEN` 环境变量，前端零改动。
- **照片 URL 可达性**：识别服务在容器/其他机器时，`cats[].photos` 必须是它**能下载**的地址。若后端在本地而识别服务在云托管，`asset-base-url` 不能填 `127.0.0.1`——必须填云托管能访问到的公网/内网地址，否则建库报 502。

## 6. 换模型 / 调参（运维必读）

所有开关在 `server/app/config.py`，可用环境变量覆盖，不碰接口与前端：

| 改什么 | 环境变量 | 默认 | 说明 |
| --- | ---- | -- | -- |
| 换 ReID 骨干(ONNX) | `REID_ONNX` | 空（自动发现，优先 `mega_descriptor_t.onnx`） | 指向新 `.onnx`；dim/输出形态自动适配 |
| ReID 归一化口径 | `REID_NORM` | 自动（文件名含 `mega`/`descriptor` → `half`，否则 `imagenet`） | **配错会让向量塌缩**：MegaDescriptor 是 `[0.5,0.5,0.5]`（x/127.5−1），配成 ImageNet 后同猫余弦 < 0.3 |
| 换 timm 模型 | `REID_TORCH` | `timm/vit_large_patch14_dinov2.lvd142m` | 不设 ONNX 时自动走 PyTorch |
| 输入尺寸 | `REID_SIZE` | 224 | 首选值；`engine._probe_input_size` 会按模型 token 数反推并真跑校验后纠正 |
| 检测模型 | `DETECT_ONNX` | 空（自动发现 `models/yolov8n.onnx`） | YOLO onnx；猫类 id 在 `engine._Detector.CAT_CLASS=15`。关闭用 `DETECT_ONNX=off` 或 `DETECT_AUTO=0` |
| 抠图灰底开关 | `MATTING_MASK_EMBED` | `1` | 提特征前把背景换成灰底（`0` = 退回旧的全框裁剪） |
| 抠图覆盖率门控 | `MATTING_MIN_COVERAGE` | `0.10` | **2026-10-31 新增**：u2netp 覆盖率低于此值判定抠图失败（典型现场：提亮后的白猫，白毛与背景同色，覆盖率 40%→5%），退回原始 crop 提特征 —— 否则灰底合成图接近纯灰，特征向量塌缩成噪声，与原图余弦跌到 0.01 |
| 毛色/花纹分类 | `USE_CLIP` + `CLIP_MODEL`/`CLIP_PRETRAINED` | 关（走本地色域分析） | 三层链路：CLIP → `ATTR_API_URL` → 本地 HSV 色域；`/health.attrSource` 报实际来源 |
| 设备 | `DEVICE` | `auto` | `auto`/`cpu`/`cuda`（自动探测 CUDA） |
| 抽帧上限 | `MAX_FRAMES` | 8 | 视频最多抽帧数 |
| 特征库后端 | `INDEX_BACKEND` | `sqlite` | `sqlite` / `cos` 二选一。**云托管推荐 `cos`**：每猫一对象 `<INDEX_PREFIX><cat_id>.bin`，不依赖容器磁盘；留在 `sqlite` 则必须挂卷到 `/data` |
| sqlite 路径 | `INDEX_DB` | `/data/catcampus/index.sqlite3` | **仅 `INDEX_BACKEND=sqlite` 时生效**；文件 `cat_index` 表存向量 |
| COS 参数 | `COS_SECRET_ID` / `COS_SECRET_KEY` / `COS_BUCKET` / `COS_REGION` | 空 | `INDEX_BACKEND=cos` 时必填；`INDEX_PREFIX` 默认 `index/` |
| 特征库版本 | `FEATURE_POOL_VERSION` | `4` | 换骨干时 +1：sqlite/COS 读取时版本不符的向量直接跳过，防止新旧混算（v2=DINOv2 / v3=MegaDescriptor / **v4=切换 MegaDescriptor 后的干净重建基线**） |
| 标准照生图服务 | `IMAGE_GEN_URL` / `IMAGE_GEN_TOKEN` / `IMAGE_GEN_MODEL` | 空 / 空 / `agnes-image-2.1-flash` | `/v1/photo/standard` 的图片生成后端。默认 agnes 图片模型（**带原图 i2i**）；`IMAGE_GEN_URL` 用于接其它服务商。两者都空时该接口返回 503，不会伪造图片 |

**换模型后必做**：

1. `FEATURE_POOL_VERSION` +1（`config.py`）——旧向量被版本过滤自动失效，无需手动清库。
2. **重标定阈值**：校准中点 `SIM_MID` 是按骨干真实分布定的（v3 MegaDescriptor：不同猫余弦均值 0.22；v2 DINOv2：不同猫均值高达 0.65）。换模型后务必用实拍图重测「同猫/异猫」分布再调，否则展示分整体漂移。
3. 重启服务加载新模型。

## 7. 当前默认配置（参考）

- 模型：**MegaDescriptor-T-224**（动物 ReID 专用，HuggingFace `BVRA/MegaDescriptor-T-224`，1.3MB / CPU 59ms），输出 **768 维**，`models/mega_descriptor_t.onnx`；旧 DINOv2-base（86.8MB，`models/reid.onnx`）留作回退
  - 实测对比（19 张实拍，检测+抠图+提特征同链路）：增强 Top1 **97.4% vs 95.6%**，不同猫余弦均值 **0.223 vs 0.654**（分数可校准性碾压）
- 归一化：`half`（x/127.5−1）——不是 ImageNet，配错向量塌缩
- 阈值：logistic 校准（`SIM_MID=0.42`/`SIM_SLOPE=25`），`MIN_SIM=0.30`，`IDENTIFY_MIN=45`，`GAP_CLEAR`（Top1 与次名差过小压低分）
  - ⚠️ `MIN_SIM` 必须跟着骨干走：MegaDescriptor 同猫余弦实测只有 **0.364~0.667**（DINOv2 时代为 0.75+），沿用 0.62 会把 7/8 张真匹配挡在门外。换模型务必重测分布再调（见排查手册「八之六」）
- 查询端：单帧走**三视图平均**（灰底外扩 + 原始 + 核心框，`QUERY_MULTI_VIEW=True`）；多帧保留翻转 TTA
- 视频：ffmpeg 抽帧，速率按「时长/帧数」自适应，上限 4fps
- 抠图：u2netp（4.4MB），灰底合成提特征 + `MATTING_MIN_COVERAGE=0.10` 失败回退
