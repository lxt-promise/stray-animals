# MVP 方案

## 产品定位一句话

**校园流浪猫的「图鉴 + 协作」小程序**：让学生用游戏化方式记录校园猫，让社团用数字化工具管理 TNR、排班和资金。

## 双轮模型

```
     学生侧（拉新 / 活跃）                    社团侧（壁垒 / 价值）
  ┌──────────────────────┐              ┌──────────────────────┐
  │ 猫谱 · 图鉴收集        │              │ TNR 台账              │
  │ 目击打卡 · 猫粮值      │ ──产生数据──▶ │ 喂猫排班 · 任务认领    │
  │ 校园猫地图            │ ◀──提供内容── │ 资金公示 · 入社审核    │
  └──────────────────────┘              └──────────────────────┘
        学生打卡产生的目击数据，正是社团做 TNR 决策的情报来源
```

- **学生侧**解决「为什么打开」：撸猫的快乐 + 图鉴收集（CatchCat 已验证的机制）
- **社团侧**解决「为什么留下」：换届时数据不丢、绝育进度可量化、钱花在哪可公示

## 范围界定

**做**：猫档案 CRUD、目击打卡、校园地图、积分图鉴、TNR 台账、任务排班、资金记录、成员与入社审核、内容安全、多校数据隔离。

**本期砍掉**：

| 砍掉的 | 原因 |
|---|---|
| 智能猫屋 / 直播 / 云投喂 | 重资产、高校明确抵制、直播暴露猫位致虐猫事件 |
| 支付 / 众筹 | 个人主体开不了微信支付，等企业主体 |
| 公开评论区 / 论坛 | UGC 合规风险 + 审核成本，用目击描述代替 |
| AI 猫脸识别 | 校园猫几十只量级，人工认脸够用；二期可接 |
| 领养匹配 | 重度依赖运营，二期做（可做领养平台的入口跳转） |

## 角色与权限

| 能力 | 爱猫同学 | 社团成员 | 管理员 |
|---|---|---|---|
| 浏览猫谱 / 地图 / 动态 | ✓ | ✓ | ✓ |
| 目击打卡 | ✓ | ✓ | ✓ |
| 编辑猫档案 | ✗ | ✓ | ✓ |
| TNR / 排班 / 资金 | ✗ | ✓ | ✓ |
| 入社审核 / 角色管理 | ✗ | ✗ | ✓ |
| 看精确点位 / 内部备注 | ✗（坐标模糊化） | ✓ | ✓ |

**首个注册用户自动成为管理员** —— 冷启动关键设计。

## 数据模型（8 个集合）

| 集合 | 关键字段 |
|---|---|
| `schools` | name, campus, city, center{lat,lng}, scale |
| `users` | _openid, nickName, avatarUrl, role, schoolId, points, sightingCount, catSeen[] |
| `cats` | name, alias, sex, pattern, sterilized, earMark, status, health, characters[], location{lat,lng,name}, spotPrivate, photos[], note, internalNote, medicalNote, schoolId |
| `sightings` | catId, pending, location, photos[], health, note, reporter, points, schoolId |
| `tnr_records` | catId, status, trapDate, surgeryDate, releaseDate, hospital, cost, earMark, operator |
| `tasks` | title, type, date, spot, assignee, status, contact |
| `funds` | type(income/expense), amount, category, title, date, proof[] |
| `applies` | _openid, nickName, contact, reason, experience, status |

所有集合权限设为「仅管理端可读写」，客户端一律经云函数访问。

## 游戏化设计

| 行为 | 猫粮值 |
|---|---|
| 目击打卡 | +10 |
| 上报未建档的新猫 | +30 |
| 首次遇见某只猫（图鉴 +1） | +20 |
| 参与 TNR 记录 | +50 |
| 每日打卡上限 | 60（防刷分） |

毛色稀有度：橘/狸花常见，奶牛/纯黑少见，暹罗/纯白稀有，三花/玳瑁史诗。
**注意**：游戏化只加在「记录」行为上，绝不加在「投喂」行为上 —— 街猫的教训是付费投喂会把公益异化成消费。

## 里程碑

- **M0（本次交付）**：可运行的完整代码 + 部署文档。目标：在一个学校跑起来。
- **M1**：找 1 所学校试点，导入真实猫口数据（50-200 只），跑通 TNR 全流程。
- **M2**：复制到 3-5 所学校，沉淀「开校 SOP」（建校 → 导入 → 招新 → 首月 TNR）。
- **M3**：升级企业主体，接支付做绝育众筹；评估接 AI 猫脸识别。

## 冷启动建议（你没有社团资源）

1. **别先写代码再找学校**，也别空手去谈。用现在这套可运行的小程序作为「见面礼」：社团最痛的是换届丢数据，你能直接解决。
2. **谈判筹码排序**：数据不丢 > 招新工具 > 资金公示 > 减少重复劳动。别谈「公益情怀」，谈「你们明年换届后这 200 只猫的资料还在不在」。
3. **首批只做一所学校**，把绝育率从 X% 提到 70% 以上，这就是最好的案例。
4. **地推靠学生侧功能**：图鉴 + 打卡 + 校园地图，天然适合社团公众号/QQ 群传播。CatchCat 证明了这类机制的自传播力。
