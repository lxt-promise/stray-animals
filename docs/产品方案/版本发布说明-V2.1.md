## 四、提审备注（强烈建议填，直接影响审核员判断）

```
【本次为整改后的持续迭代版本】
此前版本已完成社交-笔记类目风险的整改（打卡改为结构化选项、可见性由管理员统一配置、不展示置信度、不出现「AI」字样）。本版在此基础上增强管理能力与校内互助：

【功能说明】
本小程序是校园流浪猫信息管理查询工具，主要功能：
1. 猫谱查询：按毛色/花纹/状态检索本校已登记流浪猫档案（档案由校内社团成员创建维护）
2. 目击打卡：以结构化选项记录看到某只猫的时间、地点、健康状况
3. 点位地图：在校园地图上展示猫咪常驻点位（对幼猫、病猫坐标做模糊化处理）
4. TNR 台账：绝育流程（诱捕-手术-放归）的记录与进度跟踪
5. 社团内部：排班任务、收支公示、成员管理（仅社团成员可见）
6. 拍照识别：对上传的猫照片提取毛色花纹特征，与本校档案做相似度比对，给出最多 2 个候选供用户确认（辅助判断工具，结果需用户确认后才记录）
7. 校内医疗互助：校内猫咪患病时，由社团发起医疗互助，社团成员自愿参与，资金收支公开可查（非公开募捐，属校内社团成员间互助）

【内容安全】
用户可上传猫照片。已接入微信官方内容安全能力：文本经 security.msgSecCheck、图片经 security.imgSecCheck 检测，违规内容不予入库。所有内容均可溯源到发布者 OPENID。

【不涉及】
不涉及在线交易与经营性支付；不涉及公开募捐（医疗互助为校内社团成员自愿参与，非向公众筹款）；不涉及社交聊天、陌生人交友；不涉及 AI 生成内容（无 AI 作画/写作/换脸等深度合成能力）。

【其他】
所有用户数据按学校 ID 隔离；猫咪精确坐标对非社团成员做模糊化处理。
```

## 七、医疗互助模块风险提示（请先决策再提审）

- 该模块走**微信虚拟支付**（`wx.requestVirtualPayment`），是个人主体下**唯一合规的收款通道**；个人主体**开不了微信支付商户号**。
- 文档（`docs/业务规则/募捐模块.md`）已注明：用户选「复用虚拟支付」收真实善款属平台规则**灰区**，**完全合规的公益募捐需升级企业/个体户主体 + 微信支付商户号**。
- 审核风险：个人主体下「向公众筹款/募捐」是敏感点。本版若带着该模块提审，**建议在端内文案避免「捐赠/募捐/支付」**，并在提审备注里明确「校内社团成员自愿互助、非公开募捐」（已在第四节写好）。
- **若想最稳过审**：可在本版暂时隐藏「医疗互助」入口（加开关，随时可开），等主体升级后再放开。是否隐藏由你决定——代码未改动，需你整理时自行处理。
