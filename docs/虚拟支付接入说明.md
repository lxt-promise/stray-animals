# 个人虚拟支付接入说明（模块封装版）

> 本文档对应需求：先封装虚拟支付「模块功能」，暂不与业务权益耦合。
> 支付能力由云函数 `lib/vpay.js` 统一承担，业务侧后续只需消费发货意图即可完成接入。

## 一、模块职责边界（关键）

本模块只做三件事，不决定「买了之后发什么」：

1. **下单签名** —— 云函数生成 `outTradeNo` + `signData` + `paySig` + `signature`，返回前端拉起 `wx.requestVirtualPayment`。
2. **接收推送** —— 微信发货/退款等事件推到云函数，验签 + 幂等，把「发货意图」记进 `vpay_deliveries`。
3. **查单兜底** —— 推送丢失时调用 `query_order` 主动查单，同样产出发货意图。

业务侧接入时，只需：轮询 / 监听 `vpay_deliveries` 中 `status='pending'` 的记录 → 发放对应权益 → 调 `vpayCompleteDelivery` 置为 `delivered`。这就是「解耦」的接缝。

## 三、新增的 action（云函数）

| action | 角色 | 说明 |
|---|---|---|
| `vpayConfig` | public | 返回 offerId / 沙箱标志 / 道具列表（不含密钥） |
| `vpayCreateOrder` | user | 下单签名，返回 `payData` |
| `vpayQueryOrder` | user | 主动查单（兜底发货） |
| `vpayRefund` | admin | 退款（仅 Android；iOS 会拦截提示走 App Store） |
| `vpayListOrders` | user | 我的订单 |
| `vpayListDeliveries` | admin | 待发货/已发货意图（业务侧消费） |
| `vpayCompleteDelivery` | admin | 发放权益后标记 delivery 完成（幂等闭环） |
| `vpayNotify` | public | 消息推送入口（也由 HTTP 分支自动路由，返回 XML） |

## 四、新增数据集合

- `vpay_orders`：订单（outTradeNo / wxOrderId / productId / 金额 / status）
- `vpay_notifies`：微信推送原始事件（审计）
- `vpay_deliveries`：发货意图（业务侧发放权益的依据，按 `wx_order_id` 去重）

## 五、签名算法（双签名，依据官方 5.5 节）

```
paySig    = HMAC-SHA256(AppKey,  "requestVirtualPayment" + "&" + signData)
signature = HMAC-SHA256(sessionKey, signData)
```
- `signData` 是与前端传给 `wx.requestVirtualPayment` **完全一致**的 JSON 字符串（字段顺序固定）。
- `sessionKey` 由云函数用前端 `wx.login()` 的 `code` 调 `jscode2session` 获取（见 `fetchSessionKey`）。
- B 端接口（查单/退款）的 `paySig`：`uri` 换成 `xpay/query_order` / `xpay/refund_order`。

## 六、部署前 checklist（上线必做）

- [ ] 个人主体 + 服务类目含「工具」+ 已完成认证、备案
- [ ] 已知晓并确认：个人主体全终端月支付限额 **10 万元**
- [ ] MP 后台【虚拟支付】已开通，拿到 **AppID / OfferID / 现网 AppKey**
- [ ] 在【道具管理】创建道具并发布（记录 productId + 价格，price 与下单一致）
- [ ] 云函数环境变量填：`VPAY_OFFER_ID / VPAY_APP_ID / VPAY_APP_SECRET / VPAY_APP_KEY`
      （本地调试用沙箱：`VPAY_SANDBOX=true` + 沙箱 AppKey；真机联调务必切现网）
- [ ] 【消息推送】配置 Token / EncodingAESKey，并把回调 URL 指向本云函数（HTTP 分支已就绪）
- [ ] 若需 iOS 支付：配置小程序简称 + 开通苹果 IAP
- [ ] 验签逻辑与官方示例核对一致（见 `verifyNotifySignature`）
- [ ] 发货以 `wx_order_id` 幂等去重；`success` 回调可能丢失，以推送 + 查单兜底
- [ ] 上线后用小额真单验证：支付 → 推送 → 发货 → 后台账单一致
- [ ] 告知用户费率：Android 1%，iOS 12%；结算 Android T+3，iOS 约 45–60 天

## 八、前端调用示例（业务页接入时）

```js
const vpay = require('../../utils/virtualpay')

// 购买（productId/goodsPrice 来自后台已发布道具）
await vpay.pay({ productId: 'tip_1', goodsPrice: 100, buyQuantity: 1, attach: '赞助猫粮' })

// 查我的订单
const orders = await vpay.listOrders()
```
