# 喵园 CatCampus 小程序申请上线指南

从「还没有账号」到「审核通过、正式发布」的完整流程，含**可直接复制粘贴的填写文案**与避坑清单。
按个人主体撰写；文末附「升级个体户/企业主体」的差异说明。

> 政策口径核对时间：2026-09-26。类目清单、支付政策会变，最终以你在 mp 后台看到的页面为准。

---

## 总览：时间线

```
D0      注册账号（邮箱验证 + 身份证 + 人脸）      ~1 天
D1      补名称/头像/简介/类目                    ~1 天（名称可能被占，准备 5 个备选）
D1      拿 AppID → 填入 project.config.json     即刻
D1      提交 ICP 备案 ← 关键路径，最慢一环
D2-D8   微信初审（1-6 工作日）+ 工信部短信核验（24h 内必须完成）
D8-D28  省通信管理局终审（1-20 工作日，不能催）
备案通过 → 填云环境 ID → 开发者工具上传代码 → 提交审核（1-7 天）→ 发布
```

**总工期建议按 4-6 周预留**，卡点几乎都在备案。备案期间不影响开发——用**体验版**测真机。

## 第一步：注册账号

入口：https://mp.weixin.qq.com → 右上角「立即注册」→ 选「**小程序**」（别选错成公众号/视频号）

准备材料：

| 材料 | 要求 | 常见坑 |
|------|------|--------|
| 邮箱 | **未注册过**公众平台/开放平台/企业微信 | 一个邮箱只能注册一个，别用已经绑过公众号的 |
| 管理员微信号 | 本人、**已绑定银行卡**（人脸核验要用） | 没绑卡会卡在核验 |
| 身份证 | 有效期内的中国大陆居民身份证 | 过期会被退 |
| 手机号 | 本人**实名**办理 | 要收工信部核验短信，非实名收不到 |

> 同一身份证 / 手机号 / 微信号名下注册的小程序都不能超过 5 个，超了会提示「请更换管理员」。

操作：填邮箱+密码 → 收激活邮件点击链接（收不到把 `weixinteam@tencent.com` 加白名单）→ 选「个人主体」→ 填姓名/身份证号/手机号 → **管理员微信扫码完成人脸识别与短信验证** → 提交。

## 第二步：命名（有坑，先想好 5 个备选）

规则要点：

- 长度 **4-30 字符**（**一个中文 = 2 字符**，所以中文名最多 15 个字）
- 全平台**唯一**，不得与不同主体的公众号/小程序重名（同主体下可重名）
- 个人主体**额外禁止**：
  - 企业化命名（"XX公司""XX集团""XX平台"）
  - 前置审批领域词（新闻、金融、医药、宗教、医疗器械）
  - 公共事务词（监管、政务、官方）
  - 超范围经营词（**商城、商贸、店铺、售卖**）
  - 营销词（免费、促销、清仓、打折、第一、最）
- 不能堆砌热搜词，不能用纯功能性宽泛词（如叫"猫图谱"就有风险，太泛）

### 推荐名称（按优先级）

| 优先级 | 名称 | 字符 | 说明 |
|--------|------|------|------|
| 1 | **喵园** | 4 | 最简洁、好记、好传播，无违规词 |
| 2 | 喵园猫谱 | 8 | 带功能描述，"喵园"被占用时用 |
| 3 | 校园喵园 | 8 | 强调校园场景 |
| 4 | 喵园志 | 6 | 偏文气 |
| 5 | 喵园 CatCampus | 4+10 | 中英混排也允许（含空格） |

> 「喵园」很可能已被占用。**提交前先在微信顶部「搜一搜」搜一下小程序**，被占就换第 2 个。
> 名字定下后大概率要沿用到毕业，别将就。

### 小程序简称

从名称里**按顺序取字**（微信要求），建议简称 = 名称本身或前两字。"喵园"直接填 `喵园`。

### 头像

PNG，**144×144px**，不能有二维码/水印/大文字营销。项目里 `miniprogram/images/tab/` 已有素材，建议做一张橙色底 + 白色猫头剪影，和 App 暖阳柑橘配色一致。

## 第三步：简介文案（120 字符以内，可直接复制）

**推荐（稳过版，120 字符内）：**

```
校园流浪猫档案库：记录猫咪花色性格与绝育状态，支持目击打卡、点位地图、
TNR 记录与社团排班。面向校内爱猫师生，倡导科学救助。
```

计数：这段约 60 字符，安全。

**备选（更强调工具属性，弱化社区属性）：**

```
校园流浪猫信息管理工具：猫谱查询、目击打卡记录、绝育台账与投喂排班，
供校内爱猫师生自愿使用的公益工具。
```

> ⚠️ 简介里**不要出现**：社区、圈子、论坛、社交、聊天、交易、众筹、捐赠入口、商城。
> "捐赠"这个词尤其敏感——你的 `funds` 模块是**内部记账公示**，简介里千万别写"接受捐款"。

## 第四步：服务类目（最关键的一步）

路径：mp 后台 → 左侧「设置」→「基本设置」→「服务类目」→「添加」

**个人主体可选类目很少**，选错是提审被拒的头号原因。

### 推荐组合

| 顺序 | 类目 | 为什么选它 |
|------|------|-----------|
| 主类目 | **工具 → 信息查询** | 你的核心是"查猫谱、查点位、查绝育状态"。这是同类（校园/宠物类）个人小程序实际在用的类目，无需资质 |
| 备选 | 工具 → 实用工具 | 兜底选项，覆盖面最广、门槛最低 |

### 不要选的

| 类目 | 原因 |
|------|------|
| 社交 - 社区/论坛 | 个人主体**不可用**，且会引来最严审核 |
| **工具 - 图片处理** | 官方适用范围是「图片/音频/视频的**本地**制作、剪辑，**相关内容不适用于传播分享、公开访问**」，与喵园"用户上传猫照、全校公开可见"的核心直接冲突，详见下方问答 |
| 生活服务 - 宠物服务 | 听起来对口，但往往指向**经营性**宠物服务（美容/寄养/售卖），个人主体资质不足易被打回 |
| 教育 / 医疗 / 公益 | 需要前置审批或组织资质 |
| 文娱 - 深度合成（AI） | **见下文风险提示** |

### 问答：可以加「工具 - 图片处理」吗？

**能勾选上，但不建议加。** 它在个人主体开放清单里、无资质要求，所以后台点得出来；但对喵园是**负收益**，理由有三：

**① 适用范围直接冲突（最硬的一条）**
微信官方对「工具 - 图片处理」的定义：

> 适用于提供图片/音频/视频的本地制作、剪辑等服务，**相关内容不适用于传播分享、公开访问**。
> 注：如提供传播和公开访问服务，属于社交范畴，需选择【社交 - 笔记】类目。

典型对口产品是图片压缩、加水印、证件照排版、多图拼接这类**纯本地工具**。而喵园的核心恰恰是"用户拍照上传 → 猫谱公开 → 全校师生都能看"，正好落在它明确排除的"传播分享、公开访问"里。

**② 它会主动把审核员引到社交类目**
上面那条注释等于明示：一旦审核员认定你的图片内容是公开访问的，正确类目是【社交 - 笔记】——而社交类目个人主体基本不放开。**你等于自己递了一个让审核员升级审查的理由。**

**③ 加了也救不了 AI 识别**
猫脸识别是"图像**识别**/特征提取"，不是"图片制作/剪辑"，本来就不在图片处理的射程内。反过来，如果审核员把你的识别理解成 AI 图像处理，可能要求提供算法备案 + 第三方合作协议（个人主体拿不出）。

> 补充事实：微信的 AI 相关类目（深度合成 - AI 问答 / AI 绘画 / AI 换脸等）**只有企业主体能申请，个人主体无法通过**。
> 所以个人主体下不存在"给 AI 功能配一个合规类目"这条路——只能让 AI 功能作为工具类目的附属能力存在，且 UI 上不要出现"AI"字样，改叫「智能匹配」「花色比对」，降低触发深度合成审查的概率。

### 如果一定要加第二个类目，选这个

| 类目 | 匹配的功能 |
|------|-----------|
| **工具 → 预约/报名** | 入社申请、TNR 排班报名、领养意向登记——你项目里确实有这些表单，名实相符 |

原则：**每个类目都必须能在你小程序里指认出对应功能页面**，多一个不匹配的类目就多一处被打回的理由，宁缺勿滥。

> **行业通行做法**：没有精确对口类目时，用「工具」类目过审。审核看的是"实际功能与所选类目是否匹配"，
> 你的功能确实是信息查询 + 记录工具，不是内容分发平台，选工具站得住。

## 第六步：ICP 备案（必经，不能跳过）

路径：mp 后台 →「设置」→「基本设置」→ 找到「备案」区域 →「去备案」

**没有备案号 = 无法提交代码审核 = 无法发布。** 本地开发调试不受影响。

### 材料

个人主体：身份证正反面（清晰、四角完整、不反光、无遮挡）、本人实名手机号、绑卡微信号。

### 五个环节

1. **填主体信息**：自动带出实名，核对姓名/身份证号。
   **通讯地址要精确到门牌号**：`XX省XX市XX区XX街道XX小区X栋X单元XXX室`，只写到"XX路"必退。
   > 小技巧：直接填**身份证上的地址**，通常可免交居住证明。
2. **填小程序信息**：名称、简介、类目，与前面保持一致。
3. **人脸核身**：白墙/浅色背景、光线足、不戴帽子耳机口罩眼镜反光、不闭眼。
4. **提交 → 等初审**：1-6 个工作日。
5. **工信部短信核验 ← 最容易翻车**：初审通过后，工信部发短信到负责人手机（发送号 **12381**），
   **必须在 24 小时内**登录 https://beian.miit.gov.cn 输入验证码完成核验。
   超时自动驳回，要从头再来。收到短信立刻做。
6. **省管局终审**：1-20 个工作日，**无法催审**。期间保持手机畅通，管局可能回访核实，漏接容易被驳。

### 备案里的「服务内容」怎么填

- 服务内容类型：**生活服务 - 工具**（有些省份还有"宠物"可选，能选就勾上）
- 备注/服务说明（可直接复制）：

```
本小程序为校园流浪猫信息管理工具，用于记录校园内流浪猫的档案信息、
目击记录与绝育台账，供校内师生自愿使用，仅限信息查询与记录，不涉及商业经营。
```

### 「互联网信息服务前置审批项」怎么填 → 选 **以上都不涉及**

这一项**不要犹豫，直接勾「以上都不涉及」**。微信服务市场官方答复原文：

> 如你的小程序从事新闻、出版、药品和医疗器械、网约车等须经有关主管部门审核同意的互联网信息服务，
> 在履行备案手续时，应提供业务对应前置审批文件。**如不涉及，请选以上不涉及。**

**前置审批项只针对这几类**（勾了就要交对应许可证，个人主体基本拿不到 → 备案直接卡死）：

| 前置审批项 | 要求的资质 |
|-----------|-----------|
| 出版（游戏/网络出版） | 《网络出版服务许可证》 |
| 广播电影电视节目 | 《信息网络传播视听节目许可证》 |
| 药品和医疗器械 | 《互联网药品信息服务资格证书》 |
| 文化 | 《网络文化经营许可证》 |
| 新闻 | 《互联网新闻服务许可证》 |
| 网络预约车 / 互联网金融 / 校外培训 / 宗教 | 各主管部门审批文件 |

喵园做的是猫档案查询与记录，以上**一项都不沾边**。

**两个容易踩的坑**

1. **别因为"有图片/有内容"就去勾"出版"或"文化"**。用户上传猫照≠网络出版，UGC 不等于文化经营。
   勾了就会要求上传许可证，交不出即驳回。
2. **即使选了"不涉及"，名称/简介/备案备注里若命中关键词**（教育、医疗、培训、新闻、出版、直播等），
   管局仍可能要求补交《不涉及前置审批承诺书》。所以措辞上要避开这些词：
   - 你项目里有**健康状态、病猫标记、TNR 绝育记录**，容易被误判为「医疗保健」。
     一律写成 **「健康状态记录」「绝育台账」**，**不要出现**「诊疗」「问诊」「用药指导」「兽医建议」「在线问诊」。
   - 也不要写「救助知识科普培训」「救助课程」——会命中「校外培训」。

**如果页面强制要求上传承诺书**：按你所在省份的模板下载（各省名称不同，如广东是
《小程序不涉及前置审批承诺书（普适版）》，北京是《不涉及校外培训承诺书》），
打印 → 手填 → 签字 → 拍照上传。个人主体签字即可，不需要盖章。

备案通过后会拿到备案号（形如 `XX省ICP备XXXXXXXX号-X`），**建议放在小程序"我的"页底部**。

## 第七步：提审前必须做的配置

### 7.1 用户隐私保护指引（2023 起强制，没配会被直接打回）

路径：mp 后台 →「设置」→「服务内容声明」→「用户隐私保护指引」→「更新」

按你项目实际用到的能力勾选：

| 你代码里用到的 | 对应要勾选的采集项 |
|---------------|------------------|
| `wx.chooseMedia`（拍照/相册，发猫、识别） | 相册（仅写入）/ 摄像头 |
| `wx.chooseLocation`（选点位） | 位置信息 |
| `wx.getLocation`（定位，见风险提示） | 位置信息 |
| `cloud.getOpenData` / 云开发自动获取 OPENID | 无需勾选（不算个人信息） |
| 用户填昵称头像 | 用户头像、昵称 |

同时在前端**首次调用前弹窗授权**（相关 API 需配合 `wx.requirePrivacyAuthorize`）。

### 7.2 云环境 ID 替换

```js
// miniprogram/app.js
cloud.init({ env: '你的真实环境ID' })   // 原来是占位符 catcampus-1gxxxxxxxxxx
```

环境 ID 在微信开发者工具 →「云开发」→「环境」里创建/查看（形如 `xxx-1g8xxxxxxx`）。

### 7.3 云函数上传

微信开发者工具里右键 `cloudfunctions/catcampus` →「上传并部署：云端安装依赖」。
然后按 `docs/技术难点落地.md` 在云开发控制台建齐 8+2 个集合（`ai_tasks`、`ai_samples` 别漏）。

## 第八步：提交审核

路径：微信开发者工具「上传」→ mp 后台「版本管理」→ 提交审核

### 提审备注模板（强烈建议写，直接影响审核员理解）

```
【功能说明】
本小程序是校园流浪猫信息管理查询工具，主要功能：
1. 猫谱查询：按毛色/花纹/状态检索本校已登记的流浪猫档案（档案由校内社团成员创建维护）
2. 目击打卡：记录看到某只猫的时间、地点、健康状况，附带"是否已绝育"标记
3. 点位地图：在校园地图上展示猫咪常驻点位（对幼猫、病猫坐标做了模糊化处理）
4. TNR 台账：绝育流程（诱捕-手术-放归）的记录与进度跟踪
5. 社团内部：排班任务、收支公示、成员管理（仅社团成员可见）

【UGC 与内容安全】
用户可上传猫照片与文字描述。已接入微信官方内容安全能力：
文本内容经 security.msgSecCheck 检测，图片经 security.imgSecCheck 检测，
违规内容不予入库。所有内容均可溯源到发布者 OPENID。

【不涉及】
不涉及在线交易、支付、募捐；不涉及社交聊天、陌生人交友；不涉及经营性服务。

【其他】
所有用户数据按学校 ID 隔离；猫咪精确坐标对非社团成员做模糊化处理，防止被别有用心者利用。
```

## ⚠️ 三个高风险点（务必看完）

### 风险 1：AI 识别功能可能触发类目限制 —— 首发建议「弱化」

**这是当前最大的不确定项。**

微信对个人主体上架 **AI 深度合成（AI 生成内容）** 类功能的态度是明确不放开的。区分如下：

- ❌ **AI 生成**（AI 作画、AI 写作、AI 换脸）→ 属"深度合成"，**个人主体不能直接上架**
- ✅ **AI 识别 / 特征提取**（判断这是哪只猫、提取毛色花纹）→ 本质是图像识别工具，理论上更接近工具类目

但审核有主观性，且你的 AI 走第三方视觉大模型时，监管口径可能要求提供对方的**算法备案号 + 合作协议**（个人主体难以提供）。

**建议策略（分两步走）：**

| 阶段 | AI 功能模块的处理 |
|------|-----------------|
| **首发版** | 「AI 识别」入口**隐藏或降级**为"开发中"提示，主打猫谱/打卡/地图/TNR 四个纯工具功能，先把小程序发出去 |
| **稳定后** | 再单独提一版，观察审核反馈；若被要求补资质，再考虑升级个体户主体 |

> 如果你想首发就带 AI，另一个稳妥做法：在识别结果 UI 里保留现有的"演示级引擎"提示，
> 并明确标注"辅助判断，结果由用户确认后生效"——把它讲成**辅助工具**而非 AI 生成服务。

### 风险 2：UGC（用户上传照片/文字）——你的架构已经有优势

"允许用户自行发布内容"的平台，个人主体是受限的。但你的设计里有三个**加分项**，提审备注里一定要写出来：

1. **内容安全**：已接 `msgSecCheck` + `imgSecCheck`（这是审核员最想看到的）
2. **成员门槛**：猫档案**只有社团成员能建**（成员资格需管理员审批），普通用户只能打卡 — 属"受控 UGC"，不是开放社区
3. **可溯源 + 可删除**：每条记录都记了 `reporter = OPENID`

**额外建议（可选，可让我改代码）**：首发版把"打卡动态流"的默认可见范围收紧（例如仅展示"我的打卡"+"本校最近 5 条摘要"），
减少"公开社区"观感，运营一段时间后按需要放开。

### 风险 3：`wx.getLocation` 精确定位 —— 不要硬依赖

按之前讨论过的结论：**不能用作为核心依赖**。

- `wx.getLocation`（实时精确位置）类目准入严格，"仅展示附近信息、无线下导航"是被明确列举的不予通过场景；
- 提审时，代码里声明了 `requiredPrivateInfos` 但后台未开通的接口，会**直接拦截**。

**首发建议**：`app.json` 的 `requiredPrivateInfos` 只保留 `chooseLocation`（手动选点），
地图默认中心用学校配置里的 `center` 坐标。等主体升级或拿到权限后再加回 `getLocation`。

```jsonc
// miniprogram/app.json —— 首发保守版
"requiredPrivateInfos": ["chooseLocation"]
```

> 项目里 `map.js` / `recognize.js` 已经做了兼容：`listMapPoints` 不依赖实时定位；
> `recognize` 的 `location` 参数为空时自动跳过位置先验打分，不影响功能。

## 个人主体 vs 个体户/企业（什么时候该升级）

### 2026 年的一个重要新变化

**微信已于 2026 年 8 月底向个人主体开放「虚拟支付」**（全终端月限额 10 万，安卓费率 1%，iOS 走 Apple 约 12%）。
开通条件：个人主体 + **服务类目须含「工具」** + 已完成认证与备案。

对你的意义：将来想做"解锁高级功能""会员"，个人主体也能合规收款了（10 万是支付限额，不是免税额度，收入该申报照常申报）。
但注意：这只是**支付通道**，不等于所有经营资质自动解锁——AI 深度合成类目仍不对个人开放。

### 什么时候必须升级

| 触发场景 | 建议主体 |
|---------|---------|
| 只做校园猫谱/打卡/TNR，免费公益 | **个人** 即可 |
| 想上「AI 深度合成」类目 / 收企业赞助并开票 | **个体工商户**（办照简单、无需对公账户、可结算到法人个人卡） |
| 要做实物电商、线下核销、多人协作运营 / 引入外部商家 | **企业** |

> 补充：个人主体备案时承诺的是「**非经营性**互联网信息服务」。
> 若长期持续获利、收企业赞助或对外开票，法律层面建议办理工商登记（个体工商户即可），
> 因为"经营性互联网服务"与个人主体的非经营承诺存在出入，是需要注意的合规风险点。
