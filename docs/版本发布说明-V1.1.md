## 二、版本描述（提交审核页，直接复制）

```
1. 目击打卡改为结构化登记：取消自由文字描述，改为选择健康状况、投喂情况、行为特征等固定选项；打卡记录默认仅本人与社团成员可见，是否对访客公开由管理员按校区统一设置。
2. 猫谱按学校隔离：未绑定学校的用户不再看到任何猫咪档案，并提示先绑定学校。
3. 地图优化：取消拖动范围限制，可自由拖动查看；点位以最近一次目击位置为准，越界的目击不再导致整只猫从地图消失。
4. 拍照识别优化：候选结果精简为 2 只，并按毛色排除明显不可能的候选；视频识别速度提升，重复计算问题修复。
5. 我的页面改版：等级、猫粮、图鉴、打卡记录分区展示；新增图鉴收集页与积分等级页。
6. 社团工作台：新增样本管理与特征库手动建库、点位与筛选诊断工具；测试校园仅超级管理员可见。
```

字数约 200 字，在微信版本描述字数限制内。

**改写原则（别改坏）**：
- 不出现「社区 / 圈子 / 论坛 / 社交 / 聊天 / 交易 / 众筹 / 捐赠 / 商城 / AI」。
- 识别能力写成「拍照识别」「智能匹配」，**不写「AI 识别」**（个人主体无深度合成类目资质）。
- 强调「结构化登记」「由管理员统一设置」——这是本次整改的核心论据。

## 四、提审备注（强烈建议填，直接影响审核员判断）

```
【本次为整改版本】
上一版因「用户自行生成文字 + 图片并公开可见」被认定为社交-笔记类目。本版已完成整改：
1. 打卡页已移除自由文字输入框，改为结构化选项（健康状况 / 投喂情况 / 行为特征等均为固定枚举，
   数量等数值也用选择器），用户无法自行撰写叙述性文字。
2. 打卡记录的可见性不再由发布者决定，默认仅本人与社团成员可见；
   是否对访客公开由超级管理员在后台按校区统一配置（默认关闭）。
3. 云端不再接收和存储打卡描述文本字段；展示侧仅呈现结构化标签。
4. 承载用户上传内容的页面已关闭分享能力，避免对外传播。
5. 演示数据不含任何叙述性描述；后台不展示上报人个人信息。
6. 入口文案统一为「我的打卡」「打卡记录」，不再使用动态、笔记等表述。

【功能说明】
本小程序是校园流浪猫信息管理查询工具，主要功能：
1. 猫谱查询：按毛色 / 状态检索本校已登记的流浪猫档案（档案由校内社团成员创建维护）
2. 目击打卡：以结构化选项记录看到某只猫的时间、地点、健康状况
3. 点位地图：在校园地图上展示猫咪常驻点位（对幼猫、病猫坐标做了模糊化处理）
4. TNR 台账：绝育流程（诱捕-手术-放归）的记录与进度跟踪
5. 社团内部：排班任务、收支公示、成员管理（仅社团成员可见）
6. 拍照识别：对上传的猫照片提取毛色花纹特征，与本校档案做相似度比对，
   给出最多 2 个候选供用户确认（辅助判断工具，结果需用户确认后才记录）

【内容安全】
用户可上传猫照片。已接入微信官方内容安全能力：文本经 security.msgSecCheck、
图片经 security.imgSecCheck 检测，违规内容不予入库。所有内容均可溯源到发布者 OPENID。

【不涉及】
不涉及在线交易、支付、募捐；不涉及社交聊天、陌生人交友；不涉及经营性服务；
不涉及 AI 生成内容（无 AI 作画 / AI 写作 / AI 换脸等深度合成能力）。

【其他】
所有用户数据按学校 ID 隔离；猫咪精确坐标对非社团成员做模糊化处理。
```

## 六、本次提审前已修掉的敏感词（端内可见文案）

| 位置 | 原文 | 现文 |
|---|---|---|
| `pages/mine/mine.wxml` 菜单描述 | 捐赠与支出透明 | **收支公开透明** |
| `pages/fund/fund.wxml` 提示语 | 捐赠人能看到钱花在了哪只猫身上。 | **每一笔支出都可追溯到具体猫咪，成员可查看资金去向。** |
| `utils/const.js` 资金类别 | 捐赠收入 | **自愿资助**（`value` 仍为 `donate`，不影响既有数据） |

「捐赠」是审核高危词（易被判定为公开募捐），端内可见文案一律换成中性表述。
剩余「AI」「捐赠」仅存在于 JS 注释中，不渲染给用户，安全。
