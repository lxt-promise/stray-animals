# 识别服务部署到微信云开发（云托管 CloudBase Run）

> 适用对象：`server/` 目录下的 FastAPI 识别服务（`POST /v1/recognize` 等）。
> 目标：把它跑在微信小程序的「云开发 → 云托管」里，替换掉本地 `127.0.0.1:8090`。

---

## 0. 先澄清一个概念（重要）

微信云开发有两种算力，别选错：

| 算力 | 适合 | 能不能跑本服务 |
| --- | --- | --- |
| **云函数**（serverless） | 短时、无状态、事件触发 | ❌ **不能**：无 ffmpeg、不能常驻端口、冷启动会丢进程、容器体积受限 |
| **云托管（CloudBase Run）** | 常驻容器、可装系统包、可挂持久卷 | ✅ **就是它**：本质是 Knative 容器，监听 `PORT` 即可 |

**结论：识别服务只能部署在「云托管」，不是普通云函数。**

云托管的计费方式：按 CPU/内存/流量**按量计费**，实例可缩容到 0（空闲不收计算费，只收极少量流量）。校园项目 1 核 2G 起步，月费通常几十元，比单独买云主机便宜。

## 1. 改造后的镜像长什么样（已就绪）

仓库里 `server/Dockerfile` 已为云托管改造好，要点：

- `CMD` 监听 `0.0.0.0:${PORT:-8000}` —— 云托管注入 `PORT`（通常 80）即自动适配；本地 docker 不注入时回退 8000。
- 模型 `models/reid.onnx`（87MB）**直接打进镜像**，不再靠外部挂载卷。
- ffmpeg 已在镜像内 `apt-get` 装好（视频抽帧可用）。
- 特征库落在 `/data/catcampus`，由云托管「数据卷」挂载持久化。
- `API_TOKEN` **不写进镜像**，部署时在控制台「环境变量」里填（与后端 `catcampus.vision.token` 一致）。

`server/.dockerignore` 已排除 `.env`、本地缓存、调试脚本等，减小镜像。

> 如果你要换模型（比如 MegaDescriptor 或 DINOv2-large），把新 `models/reid.onnx` 放进 `server/models/` 重新构建即可；`Dockerfile` 里 `REID_ONNX` 已指向 `/app/models/reid.onnx`。

## 2. 部署路径（三选一）

### 路径 A：上传代码目录（最简单，推荐首次用）

1. 微信开发者工具 → 云开发控制台 → **云托管** → **新建服务**（服务名如 `catcampus-vision`）。
2. 服务里「**新建版本**」→ 选择「**本地代码 / 代码包上传**」。
3. 把 `server/` 整个目录打包上传（或开发者工具直接选目录）。平台会用目录里的 `Dockerfile` 在腾讯云云端构建镜像。
4. 构建完成后，「**公网访问**」开关保持开启，记下分配的公网域名，形如：
   ```
   https://catcampus-vision-xxxx-xxx.ap-shanghai.run.tcloudbase.com
   ```
   这是你后端要填的 `base-url`。

### 路径 B：本地构建镜像推到 TCR，再让云托管拉取

适合镜像大、或你希望复现构建过程可控。

```bash
# 1) 本地（需装 Docker）构建
cd server
docker build -t catcampus-vision:1.0.0 .

# 2) 登录腾讯云容器镜像服务 TCR，新建命名空间/仓库后推送
docker tag catcampus-vision:1.0.0 ccr.ccs.tencentyun.com/<你的命名空间>/catcampus-vision:1.0.0
docker push ccr.ccs.tencentyun.com/<你的命名空间>/catcampus-vision:1.0.0

# 3) 云托管「新建版本」→ 选择「镜像仓库」→ 选上面这个 TCR 镜像
```

### 路径 C：关联 Git 仓库自动构建

把 `server/` 推到 Git（CODING / GitHub / Gitee 等），在云托管「版本」里关联仓库 + 分支，每次 push 自动构建。适合持续迭代。

## 3. 控制台必填配置

### 3.1 环境变量

在云托管服务「**设置 → 环境变量**」里加：

| 变量 | 值 | 说明 |
| --- | --- | --- |
| `API_TOKEN` | 你的强口令 | **必填**，与后端 `catcampus.vision.token` 完全一致；不填则服务对全网开放 |
| `PORT` | 不用填 | 平台自动注入（80） |
| `REID_ONNX` | 不用填 | 镜像内已固定为 `/app/models/reid.onnx` |
| `INDEX_DB` | 不用填 | 镜像内已固定为 `/data/catcampus/index.sqlite3` |
| `FETCH_TIMEOUT` | 20 | 猫照片下载超时（秒），云上网络比本机慢，建议 ≥ 20 |
| `MAX_FRAMES` | 8 | 视频抽帧上限 |

> `DEVICE` 默认 `auto`：云托管是 CPU 实例，会自动走 ONNX Runtime CPU 版，无需设 `cuda`。

### 3.2 数据卷（特征库持久化 —— 必做）

云托管容器是**无状态**的，重启 / 缩容到 0 后 `/data` 里的内容会丢。特征库（`index.sqlite3`）必须持久化：

1. 云托管服务「**设置 → 数据卷**」→ 新建一个卷（类型选云存储/CFS）。
2. 挂载到容器路径 **`/data`**（注意是 `/data` 不是 `/data/catcampus`，让挂载覆盖整个数据目录最稳）。
3. 保存后**重新部署一次版本**使挂载生效。

不挂卷的后果：每次实例重启，特征库归零，识别会退化到占位引擎（所有猫返回 hash 占位分）。

### 3.3 实例规格

- 起步：**1 核 2G**（DINOv2-base ONNX 单图 ~150–400ms，够校园日活）。
- 猫数 > 50 或要做公开访问：升到 **2 核 4G**。
- 「**最小副本数**」建议设 1（避免冷启动延迟影响首次识别），或 0（省钱但首次请求慢几秒）。
- 「**公网访问**」开（后端在本地/其他环境时要走公网域名）。

## 4. 后端对接（改一处配置）

部署拿到公网域名后，改 `web/backend/src/main/resources/application.yml` 的 vision 段：

```yaml
catcampus:
  vision:
    base-url: https://catcampus-vision-xxxx-xxx.ap-shanghai.run.tcloudbase.com   # ← 换成你的云托管域名
    token: ${CAMPUS_VISION_TOKEN:这里填和云托管 API_TOKEN 一样的值}
    asset-base-url: http://127.0.0.1:8080   # 见下方「坑」
    school-id: ${CAMPUS_VISION_SCHOOL:}
    timeout-seconds: 120
```

重载后端即可。小程序不受影响（它只跟云函数通信，云函数再跟后端走）。

## 5. ⚠️ 一个必须重视的坑：猫照片要对云托管「可达」

识别服务建库/识别时，后端会把**猫档案照片的 URL** 传给它，服务再去下载这张图算向量。

- 如果后端在**本地**，`asset-base-url` 是 `http://127.0.0.1:8080`，云托管服务拿到的 URL 是 `http://127.0.0.1:8080/uploads/x.jpg` —— 这个 `127.0.0.1` 指的是**云托管容器自己**，不是你的电脑！结果：照片下载失败，建库报 `failed`、识别退化。

两种解法（二选一）：

- **方案 1（最稳，推荐）**：后端也一并部署到云托管（同一云开发环境），`asset-base-url` 填后端在云上的公网/内网域名。两个服务同环境，内网互通、延迟低。
- **方案 2（后端先留本地）**：把本地 8080 用内网穿透/公网地址暴露，`asset-base-url` 填那个**公网可达**的地址（如 `https://your-tunnel.example.com`），并确保猫照片目录 `uploads/` 能通过它访问（CORS/鉴权不影响，因为是服务端下载）。

> 简单说：**谁存猫照片，谁就必须能被云托管访问到。** 这是部署识别服务上云后最容易踩的坑。

## 6. 验证部署

```bash
# 1) 健康检查（看 provider 是不是 onnx）
curl https://<你的云托管域名>/health

# 2) 后端侧触发建库（管理员在小程序端或后端接口 POST /api/vision/build-index）
#    看返回的 built 数量是否等于猫档案数，failed 应为空

# 3) 识别测试：上传一张猫图，走后端 /api/vision/recognize，
#    候选里应能命中对应猫，分数与本地一致（同模型同阈值）
```

`/health` 返回 `provider:"onnx"` 且 `ffmpeg:true` 即说明模型与抽帧都正常。

## 7. 费用与冷启动

- 按量计费：CPU/内存按秒、流量按出网字节。1 核 2G 最小副本 1，校园小项目日常几元～几十元/月。
- 缩容到 0 时，首请求有 1–5s 冷启动（加载 ONNX 模型）。设最小副本 1 可消除。
- 流量走腾讯云已备案域名（`*.run.tcloudbase.com`），**不需要你单独备案**；若用自有域名才需备案 + HTTPS 证书。

---

## 8. 与小程序端的关系（回顾）

- 小程序 → 云函数 `catcampus`（前端） → 后端 Spring Boot（本地或云托管） → **识别服务（云托管）**。
- 小程序**不直接**访问识别服务，所以小程序端无需配服务器域名；但后端调云托管需 HTTPS 公网域名 + `API_TOKEN`（已实现）。
- 云函数出网不受小程序 `request 合法域名` 限制，这一条依然成立。
