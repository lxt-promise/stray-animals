# 特征库：一只猫存几个向量？（2026-10-25 实测结论）

## 结论先给

**维持「一只猫一条向量」，不改成多向量。** 但把聚合策略从「一律内点平均」改成
**按离散度自适应**（`config.REP_SPREAD_MIN`，已落地在 `engine.rep_vector`）。

一句话理由：多向量只有在「档案照彼此差异极大」时才赢，而**只要档案里混进一张
拍错的照片，它的 top1 会从 100% 崩到 29%** —— 真实现场后者是高频事件，前者是罕见事件。

## 怎么测的

工具：`server/tools/mv_eval.py`（新增，可复跑）

```bat
..\env\Scripts\python.exe tools/mv_eval.py --enroll-set div
..\env\Scripts\python.exe tools/mv_eval.py --enroll-set div --poison 1
```

素材：7 只猫（`data/_cats.jpeg` 四格 + `data/probe/` 三张真实照），每只 10 个变体。
指标 `margin = 正确猫余弦 − 最像错猫余弦`（top1 在这批素材上会饱和，看不出差异）。

**两个协议要点**，不这么做测出来的全是假象：

1. **建档集和查询集必须互斥**，否则多向量等于「背答案」必然赢。
   建档 = grass/wood/zoom 一类，查询 = 亮度、模糊、旋转、镜像、原图。
2. **建档集里绝不能出现原图 `orig`**。所有查询变体都由 orig 派生，orig 天然最像
   查询图 —— 谁拿到 orig 谁白赢。第一版就栽在这：`S-first`（只留第 1 张）三个场景
   全部第一，纯属协议偏差。修正后 `S-first` 才回落到正常水平。

## 数据

### 档案干净时（margin，越大越好）

| 档案照差异 | 库内离散度¹ | S-rep 单向量 | M-max 多向量 | M-top2 | M-mean |
|---|---|---|---|---|---|
| 近似重复 | 0.928 | **+0.1886** | +0.1851 | +0.1818 | +0.1832 |
| 取景不同 | 0.888 | **+0.1887** | +0.1769 | +0.1828 | +0.1779 |
| 极端差异 | 0.801 | +0.1484 | **+0.1697** | +0.1503 | +0.1319 |

¹ 同一只猫的档案照两两余弦均值。

**交叉点在离散度 0.85~0.89 之间**：照片彼此很像时，平均是**降噪**（噪声相消，
原型方向比任何单条都更靠近查询），单向量赢；照片散得开时，平均出一个谁都不像的
中间脸，多向量 max 赢。

我们线上档案照的离散度落在 0.88~0.93（检测框把猫抠出来再 letterbox 归一，
亮度/背景差异基本被吃掉），**在交叉点的「单向量赢」一侧**。

### 档案混入一张别猫照片（决定性）

| 方法 | 取景不同档案 | 极端差异档案 |
|---|---|---|
| **S-rep 单向量（离群剔除）** | top1 **100%**，margin +0.1847 | **100%**，+0.1378 |
| S-mean 纯平均（无剔除） | 100%，+0.1046 | 100%，+0.0717 |
| **M-max 多向量** | top1 **29%**，margin **−0.0153**，AUC **0.286** | **41%**，−0.0082，AUC 0.408 |
| M-top2 | 100%，+0.0998 | 98%，+0.0672 |
| M-mean | 100%，+0.0932 | 92%，+0.0623 |

AUC 0.286 是**比瞎猜还差**（0.5 才是瞎猜）—— 错猫分数系统性高于正确猫。
原因：每张错照都成了那只猫的一条门面，查询时 `max` 一定挑中它（错猫分冲到 1.000）。
而 `rep_vector` 的 medoid + 内点剔除把毒图识别成离群点直接丢掉，
**polluted 与 clean 的 margin 几乎一致**（+0.1847 vs +0.1887）。

## 顺带修掉的真问题：聚合策略一刀切

实测中发现 `rep_vector` 的 `keep_n = ceil(n × REP_KEEP)`：

| n | keep_n | 是否真剔除 |
|---|---|---|
| 3 | 3 | **否**（等于纯平均） |
| 5 | 4 | 是 |
| 8 | 6 | 是 |

也就是说**照片少的时候完全没有离群剔除**，退化成纯平均 —— 而纯平均正是污染场景下
掉分最狠的那个（+0.1821 → +0.1046）。

改为：先算这批视图的两两余弦均值 `spread`，
`spread < REP_SPREAD_MIN(0.88)` → 直接用 medoid 本身；否则走原来的内点平均。

| 场景 | 改前 | 改后 |
|---|---|---|
| 近似重复 (0.928) | +0.1886 | +0.1886（仍走平均，不变） |
| 取景不同 (0.888) | +0.1821 | **+0.1887** |
| 极端差异 (0.801) | +0.1417 | **+0.1484** |
| 取景不同 + 污染 | +0.1821 | **+0.1847** |
| 极端差异 + 污染 | +0.1292 | **+0.1378** |

五个场景全面不劣。回归测试见 `server/tests/test_scoring.py::TestRepVector`
（离散度低走 medoid / 离散度高仍平均 / 显式 keep 不被改写）。

## 如果以后还想上多向量

必须同时满足，缺一不可：

1. **建档侧做离群剔除**，且剔除后剩下的才入库（否则就是上面的 29%）；
2. 候选按 `catId` 去重改成「同一只猫的多条取最高」，否则候选列表会出现同一只猫两条；
3. `index_store` 的键从 `cat_id` 改成 `cat_id#view`，COS 每猫一对象的布局、
   `DELETE /v1/index?catId=` 的删除语义、`indexStatus` 的 ghostCount 都要跟着改；
4. 库向量数 ×3~×5，检索矩阵、重建耗时同步放大。

收益上限是极端差异场景的 +0.021 margin，代价是上面四件 + 污染场景的 71% 崩塌。
**当前不划算。**
