# 自建识别服务技术方案

> 配套代码：`server/`（FastAPI 服务，可 Docker 部署）
> 政策与版本核对时间：2026-09

## 一、结论先行

| 问题 | 答案 |
|---|---|
| 要自己训练模型吗 | **不需要**。用现成的动物个体识别骨干做特征提取即可，"建特征库"≠"训练模型" |
| 自建相对调用第三方 API 的好处 | 视频能真抽帧（云函数无 ffmpeg）、数据不出自己的服务器、长期成本趋近于零、可微调升级 |
| 最低配置 | 2 核 4G 纯 CPU 即可跑；有 GPU 更好但不是必须 |
| 对接要改多少代码 | 云函数配 2 个环境变量；前端零改动 |

## 二、调用链路

```
小程序 → wx.cloud.uploadFile → 云存储(fileId)
       → 云函数 catcampus：fileId → 临时 HTTPS 链接（content:// 协议外网不可达，必须换）
       → POST 自建服务 /v1/recognize（Bearer 鉴权）
       → 猫体检测 → 裁剪 → ReID 提向量 → 本地特征库余弦检索
       → 返回 { features, candidates }
       → 云函数融合「位置先验」后回给小程序
```

**为什么不从小程序直连服务器**：
① 云函数出网不受 `request 合法域名` 限制，省掉在 mp 后台配域名的步骤；
② 服务器接触不到微信用户身份，鉴权与安全边界更清晰；
③ 临时链接签发逻辑在微信侧，天然带有效期，比自己签发 URL 安全。

## 三、模型选型

| 环节 | 选型 | 理由 |
|---|---|---|
| 猫体检测 | YOLOv8n / YOLO11n（ONNX） | 先在图上框出猫再提特征。整图提特征会让模型"记住背景"（同一只猫总在同一块草坪前，换个地方就认不出），学术上叫 Background Problem。COCO 里猫是类别 15 |
| 个体特征 | **MegaDescriptor-L-224** | 首个专做野生动物个体识别的基础模型，在 29 个公开 ReID 数据集上训练，原论文报告显著优于通用 CLIP 与 DINOv2。CC BY-NC 4.0，非商用免费 |
| 备选 | MegaDescriptor-S-224 / 原生 DINOv2-B | S 版更快适合 CPU；原生 DINOv2 是 Apache-2.0，商用友好但个体区分略弱 |
| 毛色花纹 | CLIP 零样本分类 | 把候选写成英文短句（"a ginger orange cat"）让模型挑最像的，零标注。仅辅助展示，不参与身份判定 |

**为什么不用 ImageNet 预训练的 ResNet 直接微调**：ImageNet 的 "cat" 类里混着狮子、豹子等野生动物，纹理与家猫差异大，迁移效果差。

## 四、三级降级（保证服务永远可用）

| 级别 | 触发条件 | 表现 |
|---|---|---|
| ONNX Runtime | 配了 `REID_ONNX` 且加载成功 | 推荐生产用，镜像小、CPU/GPU 都快 |
| PyTorch + timm | 没配 ONNX，环境有 torch | 方便调试，首次联网拉权重 |
| 内置哈希引擎 | 两者都不可用 | 同一张图必得同一向量，结果稳定但属演示级 |

即使用户一时没准备好模型，服务也能起、链路也能通，方便先联调。

## 五、视频识别

云函数的 Node 环境**没有 ffmpeg**，过去只能用 `wx.chooseMedia` 返回的封面帧凑合。自建后可以：

1. `ffprobe` 读视频总时长 D；
2. 按 `fps = n / D`（限制在 0.2~4）均匀抽帧，最多 8 帧；
3. 逐帧独立检测 + 提向量；
4. **帧向量平均后再 L2 归一化** → 检索。

多帧平均明显比单帧稳：视频里猫会动、会糊、会被遮挡，单帧容易拿到废帧。

## 六、特征库为什么用 SQLite 而不是向量数据库

几百只猫 × 每条约 4KB（1024 维 float32），全表不到 5MB，**全量载入内存一次矩阵乘**就够了。
引入 Milvus / pgvector 会带来额外的运维成本和数百毫秒的网络开销，在这个量级是负优化。

判定阈值：猫数量超过 500 只，或需要跨校统一检索时再考虑接入向量库。

## 七、部署清单

1. 服务器放行端口（建议只监听 127.0.0.1，由 Nginx 反代）
2. 域名解析 + Let's Encrypt 证书（微信小程序侧要求 HTTPS）
3. `docker compose up -d --build`
4. `curl /health` 确认 `provider` 是 `onnx`
5. 执行一次建库：云函数 action `buildAiIndex`（或命令行 `tools/build_index.py`）
6. 云函数环境变量：`AI_ENDPOINT` / `AI_TOKEN` / `AI_TIMEOUT_MS=15000`
7. Nginx 配 2r/s 限流，防止被刷导致 GPU 打满

## 八、成本估算

| 方案 | 月成本 | 单图延迟 | 适用 |
|---|---|---|---|
| 4 核 8G 云主机（CPU） | 几十 ~ 两百元 | 150~400 ms | 校园项目足够 |
| L20 / 4090 GPU 主机 | 几百 ~ 一两千元 | <20 ms | 猫数上百或对外开放 |
| 第三方视觉大模型 | 按次 ~0.01~0.05 元/张 | 1~3 s | 不想运维时的过渡方案 |

校园日活几百次调用，CPU 方案每年几百块，比按量付费便宜且可控。

## 九、合规提醒（重要）

- **小程序端不要出现"AI"字样**。改为「智能匹配」「花色比对」。原因见 `小程序上线申请指南.md`：
  微信的 AI/深度合成类目仅企业主体可申请，且需算法备案；个人主体一旦被判定为 AI 类目会被拒。
- 服务端在国外或不需要对外暴露时也要强制 HTTPS + Token，避免被扫到当免费推理机。
- 用户上传的素材**用完即弃**（本服务不写盘，图片只在内存里），临时链接也有自然过期时间。

## 十、升级路径

| 阶段 | 触发条件 | 动作 |
|---|---|---|
| 0（现在） | 冷启动 | MegaDescriptor 冻结权重 + 余弦检索，零训练 |
| 1 | 发现同花色猫频繁认错 | 引入位置先验（已实现）+ 属性过滤，缩小候选池 |
| 2 | 每只猫攒够 20+ 张确认样本 | 在 MegaDescriptor 之上加一层分类头做微调 |
| 3 | 猫数 > 500 | 接向量数据库 / 引入时序（多时点代表向量） |

「识别 → 用户点确认」这个人机协同闭环每次都在自动产出标注样本（落在 `ai_samples` 集合），
阶段 2 需要的训练集是**用着用着自己长出来的**，不需要专门组织人力标注。
