# 部署指南

从零到可用约 15 分钟。

## 前置条件

- 微信小程序账号（[mp.weixin.qq.com](https://mp.weixin.qq.com) 注册，个人主体即可）
- 微信开发者工具（Stable 最新版）
- 本项目代码

## 第 1 步：导入项目

1. 开发者工具 → 导入 → 选择 `E:\Agent\project\stray-animals` 目录
2. AppID 填你自己的（测试可先选「测试号」，但云开发需要正式 AppID）
3. 若提示 `touristappid` 无效，在 `project.config.json` 里把 `appid` 换成你的

## 第 2 步：开通云开发

1. 工具栏 →「云开发」→ 开通（选**按量付费免费额度**即可，MVP 用不完）
2. 创建环境，记下**环境 ID**（形如 `catcampus-1g23456789`）
3. 打开 `miniprogram/app.js`，把 `ENV_ID` 改成你的环境 ID

## 第 3 步：部署云函数

1. 左侧文件树找到 `cloudfunctions/catcampus`
2. 右键 →「上传并部署：云端安装依赖」
3. 等待部署完成（约 1 分钟）

## 第 4 步：创建数据库集合

> **推荐做法（省事且不会漏）**：部署完云函数后，在小程序开发者工具 Console 里执行一次
> ```js
> getApp().callApi('initCollections', {}).then(console.log)
> ```
> 云函数会自动把全部 **14 个集合**建齐（幂等，重复调用不会报错）。
> 之后只需在控制台把每个集合的权限设为「仅管理端可读写」。

如果偏好手工建，云开发控制台 → 数据库 → 依次创建以下 **14 个集合**：

```
users  schools  cats  sightings  tnr_records  tasks  funds  applies
points  ai_tasks  ai_samples  vpay_orders  vpay_notifies  vpay_deliveries
```

**每个集合**：权限设置 →「仅创建者可读写」→ 改为 **「仅管理端可读写」**（自定义安全规则填 `{"read": false, "write": false}` 亦可）。

> 这一步是安全关键：所有数据读写都走云函数，客户端无直接访问权。

### ⚠️ 容易漏建的集合

漏建集合时会在**第一次用到时**才报错，报错栈在很深的 DB 调用处，很难定位：

| 集合 | 什么时候会用到 | 漏掉时的表现 |
|------|--------------|-------------|
| `ai_tasks` | 首次使用识别功能 | `-502005 database collection not exists` |
| `ai_samples` | 首次人工确认识别结果 | 同上 |
| `points` | 首次发放猫粮值 | 「猫粮明细」空白 |
| `vpay_*` | 首次涉及虚拟支付 | 支付相关接口报错 |

代码里已加**集合自愈**：用前会在后台发起建表（**不阻塞当前请求** —— 建表是一次 300~500ms 的往返，若阻塞会顶穿客户端约 3s 的调用预算，见 FAQ 的 `-504003`）；
但若云函数账号没有建表权限，仍需按上表在控制台手工建。
**推荐做法**：部署后直接调一次 `initCollections`（一条调用把所有集合建齐，并发执行、幂等可重复），比依赖自愈更可靠。

## 第 5 步：初始化与冷启动

1. 编译运行小程序，微信授权登录
2. **第一个注册的用户自动成为管理员**
3. 「我的」→ 学校 → 填写学校名称创建并绑定（会自动取当前位置作为校园中心点）
4. 「工作台」→ 开始建第一只猫的档案

## 常见问题

| 问题                                        | 处理                              |
| ----------------------------------------- | ------------------------------- |
| 云函数报 `Cannot find module 'wx-server-sdk'` | 右键云函数 → 云端安装依赖                  |
| `-502005 database collection not exists`   | 集合漏建。执行 `getApp().callApi('initCollections', {})`，或按第 4 步在控制台手工建 |
| `-504003 Invoking task timed out after 3 seconds` | 单次云函数调用超过客户端约 3s 预算。**已修**：识别改为「分步续跑」——`recognizeStart` 建任务后，每次 `recognizePoll` 只推进一个阶段（内容安全 → 档案库+临时链接 → 特征提取），阶段产物落库，下次轮询跳过已完成部分，单次调用收敛在 2.5s 内；识别接口冷启动/超时自动重试本阶段（`partial.featFails` 计数，连续 6 次降级本地引擎保底），不再整条链路重跑。若仍频繁超时：把 `AI_POLL_TIMEOUT_MS` 调小（默认 2000），或给识别服务设最小副本 1 免冷启动 |
| `msgSecCheck` 报 -604101                   | 云开发控制台 → 设置 → 全局设置，开通「内容安全」调用权限 |
| 地图无点位                                     | 猫档案里没填位置，或学校未绑定                 |
| 打卡定位失败                                    | 手机授权位置权限；或手动「点此选择位置」            |
| 换了环境 ID                                   | 只改 `app.js` 的 `ENV_ID` 一处       |

## 投喂状态与猫粮值规则

打卡页「状况」卡片里可选**投喂状态**：路过 / 本人投喂 / 已被其他人投喂。

| 行为 | 猫粮值 | 说明 |
|------|-------|------|
| 目击打卡 | +10 | 基础分 |
| 首次遇见某只猫 | +20 | 图鉴解锁 |
| 上报新猫 | +30 | 不指定猫时 |
| **本人投喂** | **+10** | 选了「本人投喂」才发 |
| **本人投喂且有照片** | **再 +15** | 照片是投喂佐证，防刷 |
| 参与 TNR 记录 | +50 | 不受日上限约束 |

- 所有打卡类奖励共用**每日 60 上限**（`points.js` 的 `DAILY_CAP`），超额自动截断，不会超发；
- 「本人投喂」会同步猫档案的 `lastFedAt/lastFedBy`，猫详情页展示「最近投喂」，避免多人重复投喂；
- 投喂状态取值前后端各维护一份白名单（前端 `utils/const.js` 的 `FEED_STATUS`，云端 `index.js` 的 `FEED_STATUS_VALUES`），**改选项两端都要改**；非法值云端回落「路过」；
- 积分明细由云端 `pointsDetail` 返回（`base/firstMeet/newCat/feed/feedPhoto`），前端弹窗只做展示——**改奖励数额只改云端 `lib/points.js` 的 `AWARD`**，改完需重新部署云函数。

## 地图卡通头像与信息弹窗

- **marker 图标**：`miniprogram/images/marker-cartoon-{花色}-{done|todo}.png` 共 16 张（8 花色 × 绝育状态），
  白底圆角气泡 + 卡通猫脸 + 茎 + 底部状态圆点（绿=已绝育 / 橙=未绝育）。
  由 `scripts/gen_marker_icons.py`（PIL 程序化绘制）生成，**改样式后重跑该脚本即可**，不要手改 PNG。
- **花色映射**：档案 11 种 `pattern` 在前端 `map.js` 的 `CARTOON_ICON_MAP` 归并到 8 张图
  （玳瑁→三花、暹罗→灰蓝、其他→狸花、缺省→狸花）。**新增花色两端都要动**：
  云函数 `lib/map.js` 的 `mapPoints` 输出字段（`pattern`/`sex`）+ 前端映射表 + 生成对应图标。
- **点击弹窗**：点 marker → `getCat({id})` 一次云调用拿档案 + 最近目击 → 半屏弹窗展示
  常驻信息 / 最近投喂 / 巡护记录；「导航到这儿」走 `wx.openLocation`（无需接口权限）。
- ⚠️ **本次升级必须重新部署云函数**：`lib/map.js` 新增了 `pattern`/`sex` 输出字段，
  旧云端不返回 `pattern` 时所有 marker 会回落成狸花图标。
